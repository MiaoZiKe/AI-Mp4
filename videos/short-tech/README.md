# short-tech：兩奈米不是尺寸（科技頻道短片，無聲版）

- 成片：`out/short-tech.mp4`（1080×1920、30fps、H.264，441 幀＝14.7 秒；**無聲**，音軌是空的）
- 字幕檔：`out/short-tech.srt`（中英）、`.zh.srt`、`.en.srt`（時間是無聲估算）
- 九格圖：`out/short-tech-review.png`
- 可旋轉的 3D 場景：`out/short-tech/scene.html`（OrbitControls，拖曳旋轉、滾輪縮放、滑桿＝組好↔爆炸圖、指到零件看名稱；three.js 0.160.0 從 unpkg 載入，要有網路）
- 旁白稿：`videos/short-tech/narration.txt`
- 研究與查證：`research.md`；分鏡：`storyboard.md`；每鏡寫法：`script.json`（`hud`＋各幕 `props.zoom`／`measure`／`overlay`）

## 風格一句話

深色科技 HUD 裡，從一支手機一路 Powers of Ten 縮放（手機→主機板→晶片→電晶體陣列→一顆電晶體，×1 到 ×10⁶、尺標 5 cm→5 mm→500 µm→5 µm→50 nm），縮到最後一級交棒給 3D 奈米片電晶體，用爆炸圖拆開、拉 HUD 尺寸線量出 5 nm 和 44 nm，收在「都不是 2」。

## 為什麼是無聲版

使用者 2026/11/14 改決定：科技頻道要用他在 Google AI Studio 生成的聲音，音色與提示詞還沒給。所以 `voice.voiceName` 寫 `"TBD-user-voice"`，**沒有送任何 TTS 請求**。時間軸用 `node scripts/three/silent-timeline.mjs short-tech` 依各幕 `durationSec`（2.8／3.0／2.9／3.0／3.0 秒）排，字平均排開，cue 就落在那些字上。
拿到聲音後：把 `voice.voiceName`／`profile` 換成使用者的設定 → `tts-take.mjs` 整篇一次 → `npm run align short-tech`（會整份覆蓋無聲時間軸）→ 重新 render。畫面全部用 cue id 寫，不用改。

## 做法（照使用者技能 docs/skills/3d-industry-explainer-video.md）

- 技能的「renderAt(t) 確定性渲染＋Playwright 逐格截圖」對應到本專案的 Remotion 逐幀渲染：每一幀的縮放、3D 姿態、鏡頭、標籤全部由幀號算出（`zoomAt`、`stateAt`），沒有即時動畫。
- 技能五段分鏡縮成 15 秒：遠景推近＝s1–s2 的縮放｜爆炸拆解＝s3｜剖面發光看原理＝s3 尾–s4（薄片光點流動、閘極脈衝、尺寸線）｜新舊方案對比＝縮成「名稱 2 vs 實際 5／44」的數字對比（15 秒放不下 FinFET 對奈米片的流速對比）｜拉遠總結＝s5。
- 程式：`src/components/three/Hud.tsx`（`VideoHud`／`CoverHud`：HUD 背景、2D 縮放圖層、HUD 外框、交棒後才掛的 3D 畫布、HUD 版標籤、尺寸線、蓋章、提問卡、頁首、字幕、出處）；`ThreeVideo.tsx` 只在開頭加了「有 `hud` 就轉給 Hud.tsx」，沒寫 `hud` 的舊片走原本的程式。顏色只讀 `src/theme.ts` 的 `THEME_3D_HUD`。
- 3D：沿用 `stage: "three"` 引擎與 `model.json`（比例照 IBM 2021 試作晶片，1 單位≈4 nm）；霧關掉（原本的霧是淺色）、閘極是金色金屬、接點改銅色。
- bloom：這台沒有 GPU，不做真的 bloom。用兩個便宜的替代：3D 畫布外圈一道青色 `drop-shadow`（像邊緣泛光）＋舞台中心的放射漸層柔光（3D 躺下後多一點暖色）；閘極脈衝本身有 halo。
- 前段（0–5.5 秒）完全不掛 3D，只有 SVG，所以每幀很便宜。

## 渲染時間

- `bench30`（第 200–229 幀，3D 段，swangle、平行數 4、dpr 1）：每幀約 0.99 秒。
- 整支 render：第一次 6 分 50 秒（平均 620 ms/幀）；修正後再渲一次，時間相近（見下）。都在任務要求的 15 分鐘內。

## 已知問題（照實寫）

1. **無聲**：沒有配音，cue 時間是平均排字估出來的；配上真的聲音後節奏一定會變，要重跑 align 與 render，並重看每個 cue 的畫面。
2. 「5 nm」尺寸線本身很短（片厚在畫面上只有約 40px），主要靠數字框讀；推近那一鏡（約 9.0–9.8 秒）閘極頂端會靠近右上的讀數框。
3. 3D 躺下的那幾幀（約 6.2–6.4 秒）主燈打在正面，薄片顏色一瞬間偏淡。
4. 交棒前的 2D 俯視圖和 3D 第一幀大致對位，但 3D 有透視，邊緣不是像素級重合。
5. 縮放圖層是幾何示意：手機、主機板、晶片、陣列都不是真實佈局，也不仿任何機型；陣列的密度只是示意。
6. 新舊方案對比（FinFET vs 奈米片）沒有做，15 秒放不下。
7. 2D 縮放的倍率是以「畫面寬度」算的，第一級 field 寫 18 cm（讓整支手機放得進畫面），所以讀數是 ×1→×10→×100→×10⁴→×10⁶ 的量級，不是精確倍數。
8. `scene.html` 需要網路載入 three.js；沒有在這台機器上用瀏覽器實際開過（沒有可用的瀏覽器自動化套件），只確認檔案生成。
