# voice-research.md — 旁白診斷與新配音做法（what-is-server 前製）

- 寫於 2026/11/12（台灣時間晚上）。**這一步沒有花任何 TTS 額度**（只跑本機量測、`--list-models`、WebSearch）。
- 使用者的兩個要求是這份文件的首要標準：
  1. 「旁白太糟糕，我需要台灣腔調，角色是親切的說明產品架構，有點像是小知識介紹」
  2. 「旁白盡量避免像 AI，但咬字要清楚，包含英文也是」
- **查證限制**：這個工作環境只能用 WebSearch，打不開原始網頁（ai.google.dev、docs.cloud.google.com、dev.to、livekit.com、simonwillison.net 都被網路設定擋下）。第 3 節的內容來自搜尋結果摘要，每一條都標了「官方摘要／第三方／未驗證」。要逐字核對官方文件，得先把 ai.google.dev 和 docs.cloud.google.com 加進這個環境的允許網域。
- 台灣腔好不好、像不像真人，**機器量不出來，最後要靠人耳**。第 1 節的數字只能說明「哪裡規律得不像人」，不能證明口音對不對。

## 1. 診斷：mstr-bitcoin-v2 的旁白為什麼聽起來糟

量測對象：`public/audio/mstr-bitcoin-v2/` 的 13 段音檔、整條 `voice.wav`、原始批次檔 `.batch-3e168ea69a.raw.wav`，加上 `timeline.json` 的逐字時間。Callirrhoe＋gemini-2.5-flash-preview-tts。量測腳本是臨時寫的（numpy，放在 scratchpad，沒進 repo），音高用自相關法估算，只供相對比較。

### 1.1 量到的數字

| 項目 | 數值 | 怎麼讀 |
|---|---|---|
| 總長／幕數／音節 | 68.7 秒／13 幕／274 音節 | — |
| 每幕語速（含停頓） | 平均 4.15 音節/秒，標準差 0.22（變異 5%），範圍 3.83–4.57 | 每一幕幾乎一樣快 |
| 短語語速（兩個停頓之間，40 段） | 平均 5.32 音節/秒，變異 7%，範圍 4.65–6.25 | 沒有「這句講快一點、那句放慢」的變化 |
| 每幕長度 | 4.1–7.1 秒，13 幕裡 10 幕落在 5.3–6.5 秒 | 像節拍器，每 6 秒一拍 |
| 句中停頓（逗號） | 23 處，0.17–0.61 秒，中位數 0.39 秒 | 每個逗號都停，而且停得差不多長 |
| 換幕停頓（原始批次檔） | 12 處，0.91–1.08 秒 | 模型把「空一行」一律念成約 1 秒，本身就很規律 |
| 換幕停頓（成品 voice.wav） | 約 0.23 秒（0.15 秒間隔＋頭尾各留 0.04 秒），只有 3 處 `pauseAfter` 是 0.33–0.53 秒 | **句號的停頓比逗號還短** |
| 句尾音高（最後 0.1 秒對整幕中位數） | 13 幕裡 10 幕下降 1.1–4.1 個半音 | 每一幕都用同一種「陳述句收尾」 |
| 音高起伏（5–95 百分位） | 每幕 10.4–13.7 個半音，平均 11.9 | 起伏不算小，但每一幕的起伏量幾乎一樣，等於同一個語調重複 13 次 |
| 每幕音高中位數 | 161–198 Hz | 切段後幕與幕之間的音高會跳 |
| 響度範圍 LRA | 原始 2.9 LU → voice.wav 2.3 LU → 成片 1.8 LU | 模型出來就很平；loudnorm 只再壓了 0.6 LU |
| BGM | 講話時比人聲低 21.5 LU | 沒有蓋住人聲 |

### 1.2 可能原因（依我判斷的影響大小排序）

1. **稿子是書面句，而且每一幕都同一個模子。** 13 幕全部是「一句話、2–3 個逗號分句、句號結束」。CTA 以前沒有任何問句，「你」只出現在 CTA，語助詞是 0 個。用詞偏書面：「卻」「已」「約」「歸零」「去留」。專案規範自己也在推這個結果：「旁白一句 15–25 字」讓每幕一樣長，「兩個標點之間 ≤26 字，超過加逗號」讓逗號變成等距的節拍。
2. **數字太密。** 13 幕裡 8 幕有數字，共 14 個以上（年份、百分比、金額）。「幣多了二十六趴，股數卻多了三十一趴，每股含幣反而少三點七趴」一幕三個百分比，聽的人來不及消化，念的人也只能一個一個報。
3. **停頓層級被後製弄反了。** 模型原本在幕與幕之間停約 1 秒。切段後重新排，換幕只剩約 0.23 秒，句中逗號卻還是 0.39 秒。聽起來像一個人不換氣一直講，卻在句子中間頓住。這是「不像人」最直接的一個原因，而且不花額度就能修（見第 7 節）。
4. **語氣提示把九個要求塞在一句話裡，其中四個是否定句。** 現行 style 是 53 字：台灣國語、像朋友、親切溫暖、咬字清楚、不捲舌、不帶兒化音、語速自然、數字放慢、不推銷不說教。沒有場景、沒有說話對象，模型只能取平均，結果就是「什麼都有一點」的平均腔。3.x 模型更是完全沒帶提示（`tts.mjs` 對 3.x 只送純文字）。
5. **沒有指定語言地區。** 請求裡沒有 `languageCode`，口音只靠那一句中文提示。Google Cloud 版的 Gemini-TTS 有列 `cmn-tw`（見第 3 節），這個變數從來沒試過。
6. **挑音色只聽了一句 16 個音節的話。** 一句話聽不出節奏問題，只聽得出音色。上次六個音色都「拼音 CER 0」，但那量的是字對不對，量不到腔調和自然度。
7. **loudnorm 不是主因。** 整條兩段式 loudnorm 用 `linear=true`，只是整體增益，LRA 從 2.9 到 2.3 主要是因為停頓被剪短。模型輸出本身就平（2.9 LU）。
8. **BGM 沒有蓋住人聲，但它是 ffmpeg 合成的正弦和弦。** 音量沒問題（低 21.5 LU），質感偏廉價，可能加重「機器做的」印象。這點我沒有辦法量化，列為待人耳確認。

**我沒辦法判斷的部分**：Callirrhoe 念出來到底是不是大陸腔（ㄓㄔㄕ 捲不捲、「息」念幾聲）。這只能聽。上一份 voice.md 的人耳確認清單到現在還是「待填」。

## 3. 上網查到的：怎麼讓 Gemini TTS 念出台灣腔和口語感

### 3.1 官方的提示寫法（來自搜尋摘要，沒有逐字核對原文）

- Gemini TTS 用自然語言控制風格、口音、語速、語調（官方 speech-generation 頁與 Cloud Gemini-TTS 頁的摘要）。
- 官方提示指南建議的結構：**Audio Profile（角色）→ Scene（場景）→ Director's Notes（導演筆記：風格、語速、口音）→ Sample Context → Transcript（要念的稿）**，再加行內 audio tags。第三方評測說導演筆記的影響最大，不必每一項都寫。
- 口音寫在導演筆記裡，寫得越具體越好。官方範例寫的是 `Accent: Brixton, London`，是一個具體的地方，不是「英國腔」。
- 具體的描述比單一形容詞有效（第三方評測：描述「聽眾感受到什麼」比寫 energetic 好用）。
- 3.1 的 audio tags：方括號、英文、放在要變化的位置、標籤之間要隔著文字或標點；號稱 200 個以上。**完整清單沒查到**，`[short pause]`、`[laughs]` 這類常見寫法是否有效未驗證。

### 3.2 第三方實測的坑（LiveKit 的提示指南，第三方）

- 標題文字 `DIRECTOR'S` 曾被直接念出來，建議改用 `### PERFORMANCE` 這類標題。
- 導演筆記裡不要引用稿子裡的字詞，否則模型可能把筆記念出來。
- 風格筆記裡寫 quiet、flat、no rush 這類字，容易得到單調的聲音。對應到中文，「平穩」「冷靜」「不急」要少寫。

### 3.3 語言代碼

- **Google Cloud Text-to-Speech 的 Gemini-TTS 語言表有 Mandarin (Taiwan)，代碼 `cmn-tw`，狀態 Preview**；另有 `cmn-CN`（搜尋摘要）。
- Firebase AI Logic 的範例在 `speechConfig` 裡把 `languageCode` 放在音色名稱旁邊（範例是 `en-US`）。
- Gemini API 的 3.8 模型頁說語言是自動偵測。
- **未驗證**：我們用的端點（generativelanguage.googleapis.com）收不收 `speechConfig.languageCode: "cmn-TW"`、收了有沒有效果。這要在試聽時當成一個變數測：加了回 400 就拿掉。

### 3.4 音色與社群心得

- **沒查到任何針對「台灣腔」的音色評比或社群實測**（PTT、Dcard、Threads、Medium 都沒有結果）。所以哪個音色中文最自然，只能靠我們自己試聽。
- 一份第三方評測（5,400 次呼叫，不含中文）說 2.5 Flash 的語音一致性比 2.5 Pro 好；官方定位則說 Pro 適合複雜提示。repo 裡的舊筆記寫「Pro 語氣較好」。
- 3.8 Flash TTS 的官方頁摘要提到地域口音、方言、行內 IPA 發音覆寫。IPA 的寫法沒查到，先不用。

### 3.5 台灣腔的語言特徵

| 特徵 | 說明 | 來源 |
|---|---|---|
| 捲舌音弱化 | ㄓㄔㄕ 帶過，不像北京腔那樣明顯捲 | 政大、台大的學位論文摘要（搜尋結果） |
| 音高上限較低 | 聲學研究：台灣華語聲調最高點是五度制的 4，北京是 5，整體起伏比較收 | 同上 |
| 字音不同 | 「星期」的「期」念二聲、「垃圾」念 lè sè、「和」可念 hàn 等 | 科普網站（品質一般）＋通識 |
| 輕聲少、沒有兒化 | 「東西」「時候」「一點」照字念 | 通識；這次搜尋沒拿到文獻摘要 |
| 句尾語助詞 | 喔、啦、欸、吧、嘛、耶、齁 | 通識；這次搜尋沒拿到語音研究 |
| 用詞 | 影片、網路、資訊、伺服器、軟體、硬碟、記憶體、程式、當機、登入、連結、雲端、螢幕、品質、預設 | 通識 |

對提示的意義：**與其列一串「不要捲舌、不要兒化」的禁令，不如直接講「台北人」這個具體的地方和人**，再補一句正面的咬字要求。稿子本身的用詞和語助詞也在幫模型定位口音。這是我的推論，要靠試聽驗證。

### 3.6 稿子口語化（第三方工具說明與行銷文章，品質一般）

- 口播稿用「聽覺思維」：因此→所以、採用→用，長句拆短。
- 用「你」對單一觀眾講話；每句一個重點。
- 前 3–6 秒決定觀眾留不留。

## 5. 三組語氣提示

共同原則：只描述人和場景，不引用稿子裡的字（避免被念出來）；不寫「平穩、冷靜、不急」；英文咬字單獨一條。

### 5.1 短版（現有 `tts.mjs` 直接能用，寫進 `voice.style`）

> 你是台北的上班族，用台灣人平常聊天的口音，跟坐在對面的朋友解釋一個小知識，語氣親切、有快有慢，每個字都講清楚，英文單字用標準美式發音完整念出來

（67 字。`tts.mjs` 會接成「…完整念出來說：」再換行接稿子。只對 2.5 系列有效。）

### 5.2 導演筆記版（標題用英文、避開 DIRECTOR'S；內文用台灣用語）

```
以下三段是給配音員的說明，不要念出來，只念 TRANSCRIPT 之後的內容。

# AUDIO PROFILE
三十出頭的台北上班族，在科技業工作，很會把複雜的東西講得很簡單。聲音親切、有精神。

# SCENE
下午在公司茶水間，朋友隨口問了一個科技問題。你放下咖啡，面對面講給他一個人聽。旁邊沒有麥克風，也沒有觀眾。

# PERFORMANCE
Accent: 台灣台北人講的國語（Taiwanese Mandarin, Taipei）。
Style: 像在聊天，不是念稿，也不是播新聞。講到有趣的地方，聲音會亮起來。
Pacing: 有快有慢。鋪陳的句子順順講，重點句放慢，重點前面留一口氣。句子講完才換氣。
Articulation: 每個字都到位，不吞字。英文單字用標準美式發音，完整、清楚地念出來，尾音不省略，念完自然接回中文。

# TRANSCRIPT
（稿子）
```

### 5.3 情境對話版（把提示寫成一段場景，讓模型「接話」）

```
（場景說明，不要念出來：台北一間辦公室的茶水間。朋友剛問了你一個科技問題。你是台北人，講話是台灣人平常聊天的口音，親切、有快有慢，像面對面講給一個人聽。你平常上班中英夾雜，英文單字都用標準美式發音念得很清楚，中文每個字也都講得清清楚楚。）

你笑了一下，放下杯子，跟他說：

（稿子）
```

這三版在 3.x 模型上會不會被念出來，**都還沒測過**。試聽時要用聽寫回讀確認。5.2 和 5.3 需要改 `tts.mjs`／`voice-audition.mjs` 才送得出去（見第 8 節）。

## 6. 建議試聽的 4 個組合

四段都念**同一段試聽稿**，長度 15–20 秒、3–5 句、句子長短不一，至少有一個問句、一個語助詞、**至少兩個英文單字**（建議 Server、IG、LINE、App 都放）。上次只聽一句 16 音節，聽不出節奏。試聽稿由寫稿的人從正式稿裡取，下面是格式示意：

> 你每天滑 IG、傳 LINE，有沒有想過，那些照片到底放在哪？
> 不在你的手機裡喔。
> 它們放在一種叫 Server 的電腦裡面。你每打開一次 App，手機就是在跟它要東西。

| # | 音色 | 模型 | 提示 | 為什麼選 |
|---|---|---|---|---|
| 1 | Callirrhoe | `gemini-2.5-flash-preview-tts` | 短版 5.1 | 對照組。音色、模型都跟上一支片一樣，只換稿子和短提示。如果這段就好很多，代表問題主要在稿子和後製 |

## 7. 稿子口語化守則（給寫稿的人，共 10 條）

1. **一幕 2–3 個短句，長短交錯（4–18 字），不要每幕都是一個三段式長句。**
   - 前：你的照片其實不在手機裡，而是存在一台你從沒看過的電腦裡面。
   - 後：你的照片不在手機裡。真的。它們躺在一台你從沒看過的電腦裡面。
2. **對「你」講話，前三幕至少有一個問句，自己問、自己答。**
   - 前：伺服器是提供服務的電腦。
   - 後：那 Server 到底是什麼？說穿了，就是一台專門幫別人做事的電腦。
3. **語助詞放句尾，每三、四句最多一個。** 常用「喔、啦、欸、吧、嘛、耶」；「齁」太重，少用。
   - 前：它不會關機。
   - 後：而且它不關機喔，一年三百六十五天都開著。
4. **書面詞換成嘴巴會講的詞。** 因此→所以；然而→不過；並且→而且；透過→靠、用；約→大概；已→已經；是否→是不是；將→會、把；卻→可是。
   - 前：使用者透過網路向伺服器發出請求。
   - 後：你的手機會上網去問它：「欸，東西給我一下。」
5. **用台灣的說法。** 影片、網路、資訊、伺服器、軟體、硬碟、記憶體、程式、當機、登入、連結、雲端、螢幕、品質。不用視頻、網絡、信息、服務器、軟件、宕機。
6. **一句最多一個數字，而且給比喻。** 連續兩幕都有數字就拆開。
   - 前：台灣 IG 用戶約一千三百六十萬，LINE 月活躍用戶兩千兩百萬。
   - 後：光是台灣，就有兩千多萬人在用 LINE。等於幾乎每個人，每天都在麻煩它。
7. **英文字要給它位置。** 一句最多一個英文字，放在分句的開頭或結尾，前後留半形空白，後面最好接逗號或句號，讓它有時間念完。第一次出現馬上用中文解釋。不要兩個英文字連在一起。
   - 前：IG LINE App 的資料都存在 Server。
   - 後：你滑的 IG，背後是 Server。你傳的 LINE，背後也是 Server。
8. **英文字的念稿寫法先定好，寫進 pronunciation.md。** Server 照原樣；IG 是兩個字母；LINE 在念稿版寫成 `Line`，避免被拆成四個字母；App 見下方「待使用者決定」。
9. **標點是呼吸記號，不是字數規定。** 逗號是小停、句號是停下來換氣、問號要上揚。句子太長就改寫成兩句，不要為了「26 字加逗號」硬塞逗號。
   - 前：它非常忙碌，因為在同一秒鐘之內，可能會有幾百萬支手機，同時在問它問題。
   - 後：它很忙。同一秒鐘，可能有幾百萬支手機在問它問題。
10. **寫完自己念一遍。** 一口氣念不完的拆開；繞口的換字（連續的ㄓㄔㄕ、同音字相鄰）；多音字換同義詞。

**待使用者決定**：App 在台灣很多人念成三個字母 A-P-P。使用者要求英文發音標準，所以我建議念成一個音節的 app；如果使用者覺得 A-P-P 才像台灣人，就照使用者的。

**跟專案規範衝突的地方**：第 1、9 條和 CLAUDE.md 的「旁白一句 15–25 字」「兩個標點之間 ≤26 字，超過加逗號」不完全一致，validate 可能會警告。使用者這次的回饋優先，是否改 validate 規則留給最後統一決定。

## 8. 後製建議

| 項目 | 現況 | 建議 |
|---|---|---|
| 切段 | 整篇一次生成後，用靜音偵測切成每幕，去頭尾靜音，再用 0.15 秒間隔重排 | **不逐句切、不重排。** 整條原始音檔直接當時鐘，換幕點取自逐字對齊的時間戳。句間的換氣和停頓保留模型原本的 |
| 幕間分隔 | 各幕之間空一行，模型一律停約 1 秒 | 按起承轉合分成 4–5 段，只在段與段之間空行；段內的句子用換行或直接接續 |
| 過長的停頓 | 一律剪到 0.15 秒 | 只處理超過 0.7 秒的停頓，縮到 0.45–0.6 秒；**句號後不短於 0.3 秒，逗號停頓不動**。原則是句號停頓一定比逗號長 |
| 頭尾靜音 | `silenceremove` −45dB，各留 0.04 秒 | 只修整條音檔的最前和最後；中間不做 `silenceremove`，避免把氣音和尾音切掉 |
| 人聲 loudnorm | 整條兩段式，I −16、TP −1.5、LRA 11、`linear=true` | 維持。`linear=true` 只是整體增益，不壓動態。不要再加壓縮器 |
| 成片 loudnorm | −14 LUFS、TP −1.5、LRA 上限 8 | 維持 −14 LUFS、TP −1.5；確認第二段是 linear 模式（不是動態模式） |
| BGM | ffmpeg 合成的正弦和弦，壓低前 −27 LUFS，講話時比人聲低 21.5 LU；sidechain ratio 6、release 350ms | **試聽樣本一律不加 BGM、不加音效。** 正片的 BGM 講話時至少比人聲低 18–20 LU；ducking 放輕（ratio 3、release 500ms 左右）避免音量起伏感。要不要換掉合成和弦，請使用者聽過乾聲版再決定 |
| 3kHz 避讓 | BGM 與音效在 3kHz 挖 −9dB | 維持，這對咬字清晰有幫助 |

### 需要的程式改動（這一步沒有做，列給後面的人）

- `scripts/tts.mjs`、`scripts/voice-audition.mjs`：目前只會組「{style}說：\n稿子」，而且只對 2.5 系列加提示。要支援整段提示範本（5.2、5.3）、對 3.x 也送提示、可選的 `speechConfig.languageCode`。
- `scripts/voice-audition.mjs`：目前固定念第 1 幕。要能指定一段 15–20 秒的試聽稿，並支援「每個組合各自的模型和提示」。
- `scripts/tts.mjs`／`scripts/align.mjs`：新增「整條不切」模式（上表前四列）。
- 用上一支片留下的原始批次檔（`.batch-3e168ea69a.raw.wav`）可以先驗證「不切、只縮過長停頓」的效果，**不花額度**。
