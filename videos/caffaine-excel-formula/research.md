# caffaine-excel-formula 查證（2026/11/17）

主旨：公式叫 AI 寫很快，但要貼上去驗算；算錯就把結果告訴它。結構 S4（計時挑戰）；AI 用法＝寫 Excel 公式。

## 實測做法（原始請求與回應在 tests/，不改字）
- 資料：tests/make_data.py 產生 data.xlsx（虛構銷售明細 20 筆，A1:E21：日期、業務、區域、品項、金額）；標準答案由 Python 直接加總，存 expected.json：G2＝51801、G3＝75301、G4＝3。
- 模型：gemini-3.5-flash-lite（Gemini API，純文字；3-flash-preview 當日額度用完）。三題各問一次（tests/run.py），回答存 ask-G2/G3/G4.json。提示先交代欄位位置，並要求不用 Excel 365 才有的新函數、不用陣列公式、只回一行以 = 開頭的公式。
- 計時＝每次 API 請求送出到收到回應的秒數：7.31、0.59、0.56，合計 8.46 秒（≈8.5 秒）；不含我貼上與驗算的時間。
- 驗算：把公式寫進 G2～G4，用 LibreOffice 24.2 headless 重算（check.xlsx → lo/check.xlsx），讀值：G2＝51801（對）、G3＝0（錯）、G4＝3（對）。
- G3 第一次的公式把日期條件寫成 ">=2026/10/1"、"<=2026/10/31"（斜線文字）。對照實驗 tests/control-result.json：用 DATE(2026,10,1) 或 ">=2026-10-01" 都算出 75301；所以在 LibreOffice，斜線文字沒被認成日期。
- 修正：把「算出 0」告訴它（tests/fix.py，1.28 秒），它改成 ">=2026-10-1"／"<=2026-10-31"，LibreOffice 算出 75301（對）。

## 數字／事實
一分鐘挑戰／3 條公式／8.5 秒（僅 AI 回應）／斜線日期在 LibreOffice 算出 0、橫線算出 75301／最後 3 條全對。

## 還不知道（片中已講）
沒有在真的 Excel 驗算：Excel 對 ">=2026/10/1" 這種條件會不會同樣算出 0，沒測。只測 1 份虛構表、1 個模型、每題 1 次。

## 不寫
「AI 寫公式一定對」；Excel 與 LibreOffice 行為相同；更大的表。
