# sample-tech-anc — 科技頻道試片：3D 產品台＋運作動畫（耳機主動降噪）

使用者看完升級版 3D 產品台後說：「很棒，但除了拆解，可以多點它物理上運作的動畫」。這支是回應：拆解只佔前面約三分之一，後面三分之二在演「降噪實際怎麼運作」。
模型沿用 `videos/bake-a/` 的示意耳機（非特定機型、沒有商標），`bake-a` 本身沒有動。

## 成片

- `out/sample-tech-anc.mp4`：1080×1920、30fps、H.264，**19.2 秒、577 幀，無聲版**（時間軸是 `scripts/ui/silent-timeline.mjs` 照字數估的，4.9 音節/秒、幕間停 0.25 秒）。沒有片尾卡（試片）。
- 九格圖 `out/sample-tech-anc-review.png`；每幕截圖 `out/sample-tech-anc/stills/`、總覽 `out/sample-tech-anc-overview.png`；字幕檔 `out/sample-tech-anc.srt`。
- 今天沒有送任何 TTS 請求。配音設定已寫在 `script.json`（Iapetus、`tech` 預設檔＋`delivery: "warm-pro"`、4.6–5.0 音節/秒），要等使用者在網頁版試聽選定後才配；配音後跑 `tts-take → align`，畫面的時間全部寫 cue，會自動對上。

## 旁白（83 字，親和專業、沒有語助詞）

1. 降噪耳機會安靜，是因為它也在出聲。
2. 拆開看，關鍵是麥克風、晶片和喇叭。
3. 外面的噪音，麥克風先收到。
4. 訊號送進晶片，算出相反的波形。
5. 振膜一振動，反相聲波送進耳道。
6. 兩道波疊在一起，剛好抵消，
7. 你只聽到安靜。

## 每鏡

| 幕 | 時間 | 畫面（對到旁白的詞） |
|---|---|---|
| s1 | 0–3.2 秒 | 耳機立著轉一圈，大標「降噪靠出聲？」第 0 幀就在。 |
| s2 | 3.2–6.3 秒 | 「拆開」躺下、沿厚度一層層分開；念到「麥克風」「晶片」「喇叭」各出一張標籤。拆解到這裡結束。 |
| s3 | 6.3–8.8 秒 | 鏡頭推到上半部。「噪音」＝橘紅色聲波圈從上方一圈圈降到外殼；「麥克風」＝外殼變透明、露出電路板，外側麥克風發出琥珀色的光並一閃一閃。 |
| s4 | 8.8–11.7 秒 | 鏡頭再推近到電路板。「訊號」＝琥珀色光點沿板上的線從麥克風流到晶片；「晶片」＝晶片發藍光脈衝；「相反」＝晶片旁的小波形卡「算出反相」，先有橘紅的輸入波，再長出一道上下顛倒的藍色波。 |
| s5 | 11.7–14.6 秒 | 電池變透明，鏡頭往下。藍色箭頭沿排線從晶片流到喇叭單體；「振膜」＝振膜上下振動（標籤「振膜」）；「反相」＝藍色聲波圈從喇叭往下穿過耳塞，鏡頭跟著往下；「耳道」＝耳塞下方出現橘紅的噪音波形與藍色的反相波形。 |
| s6 | 14.6–17.1 秒 | 鏡頭推到耳道口。「兩道」＝標出「噪音」「反相聲波」兩道互為鏡像的波；「疊」＝下面出現綠色的「加起來」的波形與「耳內音量」條，反相波加進來的同時綠線的起伏愈來愈小；「抵消」＝綠線變平，標「互相抵消」。 |
| s7 | 17.1–19.2 秒 | 「安靜」＝綠線上的標籤換成「安靜」，音量條見底；鏡頭慢慢後退收尾。 |

第 3–7 幕的出處列都寫「示意動畫：波形是示意，不是量測；實際只能抵消一部分噪音」。事實依據與查證見 `research.md`。

## 這次新增的「運作動畫」（引擎層，資料驅動）

動作的定義寫在 `model.json` 的 `actions`，每幕用 `props.run` 由 cue 觸發，可設 `speed`（速度）、`gain`（強度）、`ramp`（進出場幀數）。寫法與範例見 `docs/three-stage.md` 第五節。

| type | 作用 | 這支片用在哪 |
|---|---|---|
| `vibrate` | 零件振動／往復 | 喇叭振膜、音圈 |
| `rotate` | 旋轉件（風扇、齒輪） | 這支片沒用到（降噪耳機沒有旋轉件）；功能做了，量成本時臨時加一個來量 |
| `pulse` | 零件發光／脈衝＋光暈 | 麥克風收到聲音、晶片運算 |
| `flow` | 沿路徑流動的光點或箭頭 | 麥克風→晶片（光點）、晶片→喇叭（箭頭，跨兩層） |
| `wave` | 往外擴散的聲波圈（方向、相位、顏色可設） | 外界噪音、喇叭發出的反相聲波 |
| `trace` | 行進波形（可反相、可加倍頻） | 耳道口的噪音與反相波；晶片旁小卡裡的兩道 |
| `sum` | 幾道波疊加的結果 | 耳道口的綠線（真的是兩道波逐點相加，不是另外畫的動畫） |
| `meter` | 跟著數值動的小儀表（HTML） | 「算出反相」小波形卡、「耳內音量」條 |

另外加了 `props.shot`（鏡頭關鍵格，讓鏡頭跟著訊號從上走到下）與 `props.shift`（把某一層變透明或移開）。原本的熱循環模組沒有動：`sample-tech-3d` 的 validate 仍是 0 error、0 warning；抽第 150、300、380 幀重渲，和既有成片 `out/sample-tech-3d.mp4` 的同一幀比對，PSNR 36–38 dB，差異只在影片壓縮造成的邊緣（比對的對象是壓縮過的成片，不是改程式前留下的無損截圖，因為改之前沒有先留）。

## 渲染時間與成本

- 成片：`THREE_CONCURRENCY=4 npm run render sample-tech-anc`，畫布倍率 `fx.dpr` 1.25、不開 MSAA。577 幀花 **720 秒（12.0 分鐘），每幀 1249 毫秒**（當時機器上還有別的工作在跑）。前一次用倍率 1 是 611 秒（10.2 分鐘）。
- 每種運作動畫的成本（`node scripts/three/bench-fx.mjs sample-tech-anc --ops --rotate drvFrame --frames 5`，平行數 1、倍率 1，全開與拿掉這一種各渲一次取差）：vibrate +147、rotate +201、pulse +26、flow −379、wave +57、trace +45、sum +376、meter −192 毫秒/幀。
  **有正有負，代表都在量測雜訊（約 ±0.4 秒）以內，量不出穩定的成本**；能說的只有「每種每幀最多多零點幾秒」。這個量測是在機器同時有別的工作時做的，要更準得在機器空閒時重量、把 `--frames` 加大。
- 真正影響時間的是鏡頭遠近：全景約 2.0 秒/幀（平行數 1），推到電路板特寫約 3.5 秒/幀。

## 已知問題

- **無聲版**：節奏是估的，配音後各步的時間會跟著真的聲音移動，要重新逐格看一次（特別是 s4 三個 cue 很密）。
- **兩道波完全抵消是理想化的畫法**，實際降噪只能抵消一部分、以低頻為主。出處列有寫，但畫面本身看起來是「歸零」。
- **只演了前饋式**（外側麥克風）這一條路。模型裡喇叭旁邊那顆回饋麥克風沒有演，旁白也沒提。
- 聲波圈、光點、波形預設畫在最上層（不會被零件擋住），所以聲波圈「穿過」耳塞時是疊在上面，不是真的從裡面穿過去。
- s6–s7 的波形基準線是斜的（模型躺下後還在慢慢轉），綠線看起來略微傾斜。
- s3 念到「麥克風」時外殼才變透明，在那之前麥克風的標籤是指在外殼上（麥克風在殼下面）。
- s4 的訊號光點很小（板上那段線只有一點多個單位長），手機上要仔細看才看得到在流動；主要靠麥克風的光暈和晶片變色帶過去。
- 修了一個舊問題，但**只對有 `actions` 的模型生效**：連續渲染時零件「不透明→半透明」不會真的變透明（three.js 把不透明編進著色器，要重編）。第一次整支渲出來外殼沒有變透明就是這個原因。沒有 `actions` 的舊片（`sample-tech-3d`、`bake-a`）為了畫面不變沒有套用這個修正，它們的淡出如果有同樣的問題，這次沒有查。
- `npm run still` 的每幕截圖是在加上「s6 把喇叭與後殼淡掉」之前拍的，s6、s7 兩張的上緣還看得到後殼；成片是對的。
- audit、selfcheck 沒有跑；封面圖（`out/sample-tech-anc-cover*.png`）有產生但沒有逐張檢查。
- validate 有 3 個 warning：s2、s6 各新增 3 張標籤（建議 ≤2）、估算長度超過「風格試片 10–15 秒」的建議（這支本來就指定 15–20 秒）。
