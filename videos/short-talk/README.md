# short-talk：三十出頭，十個有六個還沒結婚（談晴說礙）

## 成片

- `out/short-talk.mp4`：**18.5 秒**（555 幀）、1080×1920、30fps、H.264＋AAC，有配音。**超過 10–15 秒的目標**（原因見「已知問題」第 1 點）。
- 配音：Sulafat／`gemini-2.5-flash-preview-tts`、`cmn-TW`、`voice.profile`＝`love` 預設＋`delivery: "chat"`。**正式 TTS 請求 1 次**（2026/11/14，紀錄在 `tts-requests.json`），沒有試聽、沒有重送。原始錄音 20.6 秒偏慢，後製 `atempo=1.08`（上限）；原始檔留在 `public/audio/short-talk/.take-00577a4b34.orig.wav`。
- 字幕檔 `out/short-talk.srt`、`.zh.srt`、`.en.srt`；分鏡表 `videos/short-talk/storyboard.json`；封面 `out/short-talk-cover.png`。
- 九格圖 `out/short-talk-review.png`；**頻道貼文 vs 短片畫面的對照圖 `out/short-talk-vs-channel.png`**。
- 渲染：555 幀約 30 秒（每幀約 0.05 秒）。

## 風格（stage: "tanqing"，照頻道實際發的貼文）

使用者不要先前的「夜窗」（實拍照片＋夜色），要照頻道既有貼文的樣子。參考圖在 `docs/channels/tanqing-ref/`（11/12 發的三張輪播圖）。這支是把那種靜態圖卡「動起來」，不是另一種風格：

- 暖米紙底（中間亮、四邊暗一點）、左上太陽雲朵＋「談晴說礙」字標（晴、礙兩字橘棕色）、襯線粗體大標（Noto Serif TC 900）、棕墨色字、**一個畫面只有一個橘色重點**。
- 圖是線稿圓角圖形，一筆一筆描出來：十個人形膠囊、圓角表單框、一碗麵、太陽雲朵；地面線下面有淡斜紋（和貼文的圖表一樣）。
- 左下「資料：來源」、右下小太陽加圓點當頁碼（一幕一頁，小太陽跟著走到那一頁，最後一頁沒有箭頭）。
- 字幕照貼文內文的樣式（黑體 48px、靠左），英文 28px。
- 動作很慢：每頁極慢推近 2.2%；換頁＝舊頁淡出、新頁從右邊平移 96px 淡入；沒有彈跳、沒有音效。
- 程式：`src/components/tanqing/`（`engine.ts`、`TanqingVideo.tsx`）；token＝`src/theme.ts` 的 `THEME_TANQING`／`LAYOUT_TANQING`（元件不寫死色碼）；檢查＝`scripts/tanqing/validate-tanqing.mjs`；襯線字型子集＝`node scripts/tanqing/fetch-fonts.mjs short-talk`（抓到 `public/fonts/tanqing/`，不 commit；**改了大標或封面的字要重跑**，validate 會擋缺字）。
- script.json 每幕 `component: "TanqingScene"`，props＝`kind`（`ai` 礙／`qing` 晴／`ask` 提問）、`title`（1–2 行襯線大標）、`figure`（`people｜form｜bowl｜mark`，裡面 `at`／`…At` 只寫 cue id）、`note`（大標下面的橘色一句）。
- 舊的夜窗元件（`src/components/talk/`）與照片沒有刪，這支不再用。

## 已知問題

1. **片長 18.5 秒，超過 10–15 秒。** 配音自己念得慢（原始約 3.6 音節/秒，設定檔要的是 4.6–5.0），已經加速到上限 1.08，還是約 3.9。要壓進 15 秒只有兩條路，都要使用者決定：(a) 重配一次（多 1 次 TTS 請求，稿子或設定檔要先改短、改快）；(b) 不重配，剪掉最後一句「明天，再講一個數字吧」，大約 15 秒。幕間停頓沒有硬壓（輕聲聊天的規則是不把停頓壓成等距），只套了 align 預設的上限 0.8 秒。
2. **「62%」截至 2026/11/14 尚未確定**（只有華視一則報導，原始統計表沒讀到），畫面出處列已寫「華視報導轉述，原始表待核對」。上片前要到戶政司核對，步驟在 `research.md` 最後一節；旁白的「十個有六個」有兩個獨立來源。
3. s01 的大標和字幕是同一句話（大標第 0 幀就在、字幕跟著念），畫面上同一句出現兩次。
4. s02 表單裡的「什麼時候結婚？」是把旁白的「那一題」寫出來（頻道介紹文的說法），屬於觀察描寫，出處列標「觀察描寫，非統計」。不想寫明可以把 `figure.ask` 改掉。
5. 和貼文的小差別：紙底比貼文略暖一點；「62%」用 Inter 粗體，貼文的數字是 Noto Sans 粗體；貼文是 4:5，短片是 9:16，所以上下留白比較多（覆蓋率檢查有 3 幕低於 40% 的警告，這個風格本來就留白）。
6. 捲舌量測（`scripts/voice-retro.py`）樣本太少（ㄓㄔㄕ 5 個、ㄗㄘㄙ 3 個，少於 8 個不可靠），差距 2.5 kHz 只能當參考，口音要人耳聽。
7. 背景音樂是 `scripts/mix.mjs` 合成的墊底音（講話時比人聲低 21 LU），沒有音效。

## 人耳確認清單

- [ ] s04「明天，再講一個數字吧」的「吧」有沒有念出來（最低字信心 0.001）。
- [ ] 「麵店」聽寫成「面店」（同音，應該沒問題）；「還」是不是念 ㄏㄞˊ。
- [ ] 口音像不像台灣人平常講話、有沒有深夜電台的氣音。

## 重做指令

```
node scripts/tanqing/fetch-fonts.mjs short-talk      # 改了大標才要
flock /tmp/aimp4-render.lock npm run align short-talk
npm run validate short-talk
flock /tmp/aimp4-render.lock npm run still short-talk
flock /tmp/aimp4-render.lock npm run render short-talk
```

注意：不要再跑 `node scripts/tts-take.mjs short-talk`（含 `--resplit`）以外的生成；`--resplit` 會沿用已加速的錄音重切，不花請求。`--force` 會多花 1 次請求，要先問使用者。
