## 風格說明

- 全片是一個深色的自製軟體介面，一路演到底：聊天視窗 → 提示詞編輯器 → 流程節點圖。
- 會動的東西都是「介面在動」：輸入框逐字打字、滑鼠游標移過去按送出、訊息泡泡跳出來、AI 輸入中的三個點、欄位念到哪個亮哪個、標籤飛到上面排成一列、連線流進 AI 節點、回覆逐字出現。
- 打字時畫面會往輸入框推近一點，送出後退回（教學錄影常見的自動放大）。
- 和紙拼貼的差別：沒有紙紋、照片、膠帶；用深色底、圓角視窗、四個強調色（紫／藍／綠／橘）。可以用淡入淡出。
- 視窗、游標、圖示都是自己畫的，沒有任何真實產品的商標或介面截圖；AI 頭像只是寫著「AI」的方塊。

## 怎麼做的

- script.json 頂層寫 `styleVersion: 3` 加 `stage: "ui"`：配音、對齊、時間軸、字幕檔、混音都沿用 v3 的流程，只有畫面換成 `src/components/ui/`。不需要跑 `make-paper.py`。
- 元件：`engine.ts`（把各幕 props 的 `at` 換成絕對幀）、`parts.tsx`（游標、點擊波紋、打字、視窗外框、圖示）、`Tracks.tsx`（頁首＋進度條、字幕列、出處）、`UiVideo.tsx`（聊天視窗段、編輯器與流程段、封面）。
- 色票與版面：`src/theme.ts` 的 `THEME_UI`、`LAYOUT_UI`；元件沒有寫死色碼。
- 每幕 `component: "UiScene"`，props 用到的區塊：`hook`、`draft`（要打的字）、`send`、`reply`（含 `stamp`）、`editor`（含 `guide`、`slotsAt`）、`slots`、`run`（含 `node`）、`result`（含 `badge`）。所有時間都寫 cue id 或 `start｜voice｜end｜exit` 加減幾幀，沒有手填秒數。
- 檢查規則：`scripts/ui/validate-ui.mjs`。
- 指令（都要包 `flock /tmp/aimp4-render.lock`）：
  - `node scripts/validate.mjs sample-ai-ui`
  - `NODE_USE_ENV_PROXY=1 node scripts/tts-take.mjs sample-ai-ui`（會花 1 次 TTS 額度；現在的音檔已經做好，不要重跑）
  - `ALIGN_GAP_MAX=0.3 node scripts/align.mjs sample-ai-ui`（**一定要帶 `ALIGN_GAP_MAX=0.3`**，不然句間停頓會回到 0.8 秒上限，片子變長變慢）
  - `node scripts/still.mjs sample-ai-ui`、`node scripts/render.mjs sample-ai-ui`
  - 看指定時刻：`node scripts/v3/peek.mjs sample-ai-ui <out.png> 0,56,170,...`

## 配音

- 音色 Sulafat（女）、`gemini-2.5-flash-preview-tts`、`cmn-TW`、整篇一次生成。TTS 請求只送 1 次，成功，沒有重送（紀錄在 `tts-requests.json`）。
- 旁白設定檔寫在 script.json 的 `voice.profile`：二十八歲左右的台灣女生創作者，語速目標 4.6–5.0 音節/秒，語氣明快。
- 語速（63 個音節）：

|---|---|---|---|
| 模型原始錄音 | 15.45 秒 | 4.08 音節/秒 | 字念得快（第一句約 6.7 音節/秒），但句子之間停 0.4–0.9 秒，所以整體偏慢 |
| 後製加速 | 14.52 秒 | 4.34 音節/秒 | `ffmpeg atempo=1.06`（上限 1.08 以內；原始檔留在 `public/audio/sample-ai-ui/.take-cf61b1d813.orig.wav`） |
| 成片 | 13.27 秒（開口到收聲） | 4.75 音節/秒 | 對齊時把幕與幕之間的停頓縮到最多 0.3 秒（`ALIGN_GAP_MAX=0.3`）。沒有動到句子本身 |

- 捲舌指標（`scripts/voice-retro.py`，量原始錄音）：ㄗㄘㄙ 與 ㄓㄔㄕ 的擦音重心差 3.96 kHz。樣本只有 8 個和 4 個字，低於可靠門檻，這個數字只能參考。之前被聽成中國口音的 stock-jensen 是 4.4，love-stats 是 2.9，所以這支的口音要用耳朵確認。
- 對齊信心：整篇 0.84；各幕 0.78–0.94，都高於 0.5。
- 音高中位數 214 Hz。
- 沒有跑聽寫（`--asr`）確認提示有沒有被念出來。間接證據：開口前只有 0.17 秒、收聲後 0.27 秒，沒有多出來的說話聲。

## 渲染

- 全片渲染 20 秒（417 幀、每幀 48 毫秒、concurrency 4），加上混音不到 1 分鐘。每幕截圖加封面約 40 秒。
- 混音：背景音樂加 1 個轉場音效，整體 −14.3 LUFS。

## 已知問題

1. 第一幕截圖的空白帶 300px，覆蓋率檢查還有一個警告（門檻 260px）。
2. 旁白說「四塊補上去」，但官方指南的原意是「不用四項都寫，用上幾項就有幫助」。正式片應該補一句。
3. 出處沒有親眼看到原文：Google 那份 PDF 的網域（services.google.com）這個環境連不上，四個要素是從搜尋摘要確認的（官網頁面、Chrome 說明頁、多篇報導說法一致）。細節在 `research.md`。
4. 這個風格目前只有這一支片用到的幾種區塊（聊天、欄位編輯器、流程節點）。做正式片要再補：程式碼區塊、前後對照、步驟清單、片尾卡。
5. selfcheck、audit 沒有跑（它們的門檻是照 v2／v3 紙拼貼訂的）；評審圖是用 ffmpeg 抽九格加 PIL 標字做的，不是 `review-sheet.py`。
6. 句間停頓是用 `ALIGN_GAP_MAX=0.3` 壓短的。專案規範後來改成「不把句間停頓壓成等距，要趕時間就刪字」，這支沒有照新規範重做（重做要重配音）。
7. 專案規範的停工線是台灣時間 07:00；這支是下午做的，因為你當下明確要求先做，所以照做了。
8. 修正後的版本還沒有獨立評審重看。
