# 科技頻道 3D 試片：專家評估整理（2026/11/14）

評估對象：`out/sample-tech-anc.mp4`（耳機主動降噪，舊版 19.2 秒）與 `out/sample-tech-3d.mp4`（手機均熱板，14.7 秒）；對照組是使用者指定的 `videos/tech-cowos/`（63.8 秒）。
三位評審分別從「留存」「畫面」「稿子與事實」看，都是抽格看畫面加讀稿，沒有聽聲音（耳機片是無聲估算時間軸）。分數是主觀評分（滿分 10），不是量測。
評審沒有引用平台數據；「前 3 秒決定去留」「結尾預告有助追看」是業界通則，改了之後留存會不會上升，要上片後看後台的留存曲線（第 3 秒、第 10 秒、結尾）才知道。

精簡版檢查清單在 `docs/channels/tech-3d.md`；照這份改的第一支是 `videos/sample-tech-anc/`（留存改版，約 29 秒）。

## 一、三位的共識

1. **方向對，運作動畫是這個風格最值錢的東西，但它出現得太晚。** 耳機片第 7 秒才有第一圈聲波，最好看的「兩道波疊成平線」在第 15 秒之後；前 3.5 秒只有產品原地自轉加一句問句標題，看起來像商品頁，不像「有事要發生」。前 3 秒三位給 4、4.5、5 分。
2. **全片是一條直線的流程說明，沒有衝突，也沒有讓人追下去的理由。** 第 2 秒就把答案講完，後面只是驗證；中段每一步都「成功」；結尾停在「你只聽到安靜」，沒有提問、沒有下一集。繼續看的理由三位給 4、5、5.5 分。
3. **事實分寸說得太滿。** 旁白「剛好抵消」「你只聽到安靜」、綠線變成完全平的直線、音量條見底，都比 research.md 第 5 點（只能抵消一部分、低頻為主）滿；更正只放在手機上讀不到的出處小字。

其他三位都提到的：主體太小、下方約三分之一是空的；出處列字太小；零件標籤一次貼三個；3D 很貴，新增的東西要盡量做在 2D 疊層。

## 三、每條建議採不採用

### 採用（這次已經做進 sample-tech-anc）

| 建議 | 做法 | 理由 |
|---|---|---|
| 第 0 幀就有後果或反差的大字，加一個正在發生的動作 | 大標「出聲才會安靜」；第 0 幀紅色噪音圈已經在往耳機撞，下方「耳朵聽到的」面板裡紅色波形在跑 | 三位共識第 1 點 |
| 前 3 秒先給結果，再拆開解釋 | 念到「安靜」：藍波加進面板、粗線變成小小的綠波、蓋章「安靜」；念到「出聲」：耳機往耳塞那一側放出藍色聲波圈、蓋章「它在出聲」 | 把第 15 秒的 payoff 搬到開場當預告 |
| 開場不要整圈自轉 | 只轉約 25 度（`spin.turns: 0.07`），固定在看得到耳塞的側面 | 自轉是商品展示的語言；也讓人認得出是耳機 |
| 把 CoWoS 的「蓋章」搬過來 | 新的 2D 疊層 `stamp`（先大後小、微歪） | 不增加 3D 成本 |
| 先問再答 | 第 2 句「多一個聲音，怎麼會更安靜？」，畫面蓋「聲音＋聲音＝安靜？」 | 讓觀眾有東西要等 |
| 逐步揭曉、畫面一直累積 | 步驟列「3 個零件」，三格先是「？」，念到麥克風／晶片／喇叭才各自亮起來並留著；零件標籤也改成講到才貼、講完退場 | 仿 CoWoS 一層一層堆 |

### 沒採用

| 建議 | 理由 |
|---|---|
| 另外加一幕「捷運上一戴，轟隆聲就不見了」 | 片長上限 30 秒，優先給衝突與下一集；正式長片（45–75 秒）建議加回來 |
| 先演「兩波同相疊加變更吵」再翻過來 | 多一個概念、多 3 秒；正式長片可以考慮 |
| 加耳朵或頭部的剪影讓人認出是耳機 | 要新建模型零件；先用側面角度解決。不畫真人的原則下剪影也容易做醜 |
| 耳機本體換成中間調顏色、加邊緣光 | 會動到 `bake-a` 沿用的模型配色與材質，這次不動別人的資料 |

| 「晶片來不及算，所以跟不上」的說法 | 沒有夠好的來源；改成只講現象「變化快的就對不準」，依據是查到的「高頻波長短、相位要對得很準」與廠商說明（research.md 第 6 點） |

## 五、前 3 秒與留存檢查清單（科技頻道每支 3D 片都要過）

前 3 秒
1. 第 0 幀就看得到：一句肯定的反差或後果大字（≤8 字、≥120px），加上一個**已經在動**的東西（聲波、熱、流動），不是只有產品在轉。
2. 3 秒內至少 4 個事件（貼上、蓋章、變色、出現、推鏡），第一個事件在 1 秒左右，而且是「結果」。
3. 文字和畫面互相印證：標題說「出聲」，畫面就要有東西在出聲。
4. 開場不整圈自轉；角度要一眼認得出是什麼產品。
5. 最好看的運作動畫（payoff）在前 3 秒先預告一次，簡化版就好。
6. 封面與第 0 幀單獨看得懂。

繼續看的理由
7. 答案不要在第 2 秒講完：鉤子後面接一個問句，答案留到中段。
8. 逐步揭曉：零件名稱講到才出現，並留在畫面上累積；同一時間新的標籤 ≤2 張。
9. 中段要有一個畫得出來的衝突（哪裡接不上、對不準、壓不住），用叉叉或對照畫出來。
10. 給了答案之後補一句限制（「可是…還是…」），而且限制要有查證來源。
11. 每 2–4 秒有事件；3D 鏡頭慢，事件靠 2D 疊層補。結尾前不留 1.5 秒以上的靜止。
12. 回到觀眾的生活一句（什麼情況有感、什麼情況沒用）。
13. 結尾兩件事：一個具體提問，一個下一集鉤子。下一集的主角是本集畫面上一直在、但沒解釋的零件；沒查證的題目不預告。

事實與成本
14. 示意動畫不畫成「歸零」「完美」：留殘餘，儀表不標數字，旁白用「一大半」「通常」。重要的限制寫進旁白，不只放出處列。
15. 同一個零件全片只有一個名字；專有名詞出現時馬上解釋，或換成白話。
16. 出處列 ≥28px、一幕一句。
17. 新增的畫面先想 2D 疊層（`props.overlay`），3D 只用在開場、拆解、訊號流；動工前估渲染時間（每幀約 1.2–2 秒），正式長片先跑 `bench30`。
18. 上片後看後台留存曲線的三個點（第 3 秒、第 10 秒、結尾），一次只改一個變因。

## 六、評審看過的東西與沒看的東西

- 都看了三支片的抽格拼圖（前 3 秒、全片）與 script.json 的旁白；兩位用的抽格比指定的疏（每 6 幀、每 0.5 秒），秒數有 0.2–0.5 秒誤差。
- 沒有人聽聲音；沒有人上網查平台資料；只有一位逐條核對了耳機片的 research.md，均熱板片的事實沒有人核對。
- 評審建議裡的事實性內容（通透模式、第二顆麥克風的用途、均熱板的限制）當時都還沒查證；這次用到的兩點（低頻較有效、朝內的回饋麥克風）已補進 `videos/sample-tech-anc/research.md`。
