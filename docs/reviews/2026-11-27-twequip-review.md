### 四、程式 diff 審查（align.mjs、recording-timeline.mjs、pad-recording.mjs）
**沒寫 holdSec／headSec 的片：行為不變** ✅。align.mjs：holdSec 分支要 `typeof sc.holdSec === "number" && > 0` 才進去；沒寫 headSec 時 `headF = TRANS`，跟原本的式子一模一樣。recording-timeline.mjs 也一樣（headF＝TRANS）。pad-recording.mjs 是新工具，不會自動跑。
自己用假邊界實測 pad-recording（10 秒正弦波、三幕 [0.2–2.0]／[2.5–5.0]／[5.6–9.6]，套用本片 s1～s3 的 head／hold）：輸出 16.00 秒＝補 1.04＋3.9＋1.06 秒，新的人聲區間 s2 3.54、s3 10.54，跟手算一樣 ✅（測試檔已刪掉）。fa.py 的 `u.i` 是合併念稿的字元索引，按幕切分的對應是對的。
沒有會弄錯一般片的 bug。有 4 個小缺陷（不擋本片）：
1. **片尾卡前一幕的 holdSec 沒有作用**：無聲片尾卡的起點固定是 `p.voiceEndFrame − EXIT_AFTER_VOICE`（align.mjs 跟 recording-timeline.mjs 都一樣），holdSec 只會加大「到下一個有聲幕」的間隔。所以本片 s12 的 holdSec 0.5 配音後會不見；pad-recording 補在錄音最後面的靜音也會被片尾卡蓋掉。修法：silent 分支的 startFrame 再取 `max(…, p.voiceEndFrame + round(prevSc.holdSec*FPS) − TRANS)`。
2. **align.mjs 下一幕 headSec 用索引拿**（`script.scenes[i + 1]`），本幕卻是用 id 找（`find(x => x.id === c.id)`）。manifest 跟 script 的幕順序不一樣、或少一幕時，會拿到別幕的 headSec。修法：改用 `cs[i + 1]?.id` 去 script 找。
3. **文件跟程式不一致**：three-stage.md 第十四節寫「v3 take 模式下」，可是程式條件只有 `V3`，非 take 的 v3 也會套用。行為沒有錯，文件要改成「v3（含 take）」。
4. **recording-timeline 錄音沒涵蓋的估算幕不認 holdSec**（還是用 pauseAfter／GAP）；`tts-take` 的 manifest 也有一個意思不同的 `headSec` 欄位（開口前的靜音），align 讀的是 script 那個，現在不會撞到，但名字一樣容易搞混，註解要寫清楚。
