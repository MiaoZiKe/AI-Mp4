# 科技透明圈：Andy 指出過的問題（製作前必讀、交件前逐條自查）

Andy 2026/11/24 原話：「往後只要有修正，會被我點出來的地方，需要寫進製作規範內，避免發生，以及製作影片需要參考和要注意」。

## 怎麼用
- **開工前**：每支科技片的前段（腳本、建模、2D 卡）開工前先讀完本檔。
- **交件前**：交件報告要附「Andy 修正清單自查：第 1～N 條逐條 ✅／不適用」，少這行不收件。
- **新增規則**：Andy 每點出一個問題，當天就在下面加一條。寫清楚日期、原話、發生在哪支、原因、以後怎麼做、由什麼檢查擋下。只寫在對話裡不算數。
- 與 `tech-daily-playbook.md` 第九節衝突時，以本檔較新的那條為準。

## 清單

### 聲音
1. **音色要一致**（11/24，矽晶圓-1、矽晶圓-2、光阻-1）
   - 原話：問「為何聲音矽晶圓和曝光有這麼大差異」。
   - 原因：Gemini 每次生成會隨機偏高或偏低。這三支音高中位數是 136～138 Hz，基準是 121.5 Hz（光罩-1、光罩-2）。製作時量到了偏高，卻沒有重配。
   - 以後：一律用 `scripts/three/tts-pitch-take.sh` 配音，只收 112～126 Hz，最多 3 次請求。`make-tech.sh` 在渲染前也會檢查，不合格就擋下。
2. **易念錯字一律用替身字寫念稿**（11/24，光罩-2）
   - 原話：「上集唸成喪集，光罩唸成光掃」。
   - 以後：念稿裡「光罩」寫成「光照」，「上集」寫成「上一集」（另外已有：矽寫成細、坩堝寫成甘鍋、鉻寫成各、鉬寫成目）。
   - 檢查：validate 有替身字表，念稿出現原字就報 error。
   - 刪字壓片長時，不准把詞刪成容易念錯的短詞，例如「上一集」不能刪成「上集」。
3. **語音辨識結果和稿子不同，不准用「同音」「同義」自己放行**（11/24）
   - 原因：光罩-2 的 verify4 已經聽出「上集」變成「上期」，卻被判成意思相同。
   - 以後：只要不同就標「需人耳確認」，在回報裡列出時間點，請 Andy 聽。

### 畫面
4. **有國家就標國旗，有公司就附官方 LOGO**（11/24，光罩-2，套用到所有科技片）
   - 國旗：用程式繪製，照官方比例與色彩，不用 emoji。
   - LOGO：只用官網或 Wikimedia Commons 的原檔，不重畫、不改色。來源寫在 `videos/<slug>/assets.md`。三個來源都抓不到，才改用文字並回報。
5. **動畫不准簡陋，要做到專業知識影片的水準**（11/24，光罩-2 第 10～18 秒）
   - 原話：「這部分的動畫太簡陋……做的動畫需要再細緻點，要求到專業的知識影片」。
   - 不行的做法：只放一排方塊平房加小卡車。
   - 要的做法：廠房看得出是什麼廠（外牆、屋頂機組、掛 LOGO 的廠牌、國旗旗桿）；運送路線有方向感；資訊卡要有 LOGO、國旗和數字條，逐列進場；每 2～4 秒有一個跟著旁白發生的事件。
6. **交件前先給獨立審片人審**（11/24）
   - 原話：「影片請人幫我先審閱，確認哪裡還需要優化，交由對應人員進行」。
   - 以後：每支渲染前，由沒參與製作的審片人依本檔與 `tech-3d.md` 審一遍，報告寫在 `docs/reviews/`。必改項目修完才准渲染。評分 8 分以上才算專業知識影片。
7. **重做時不一定整支重做，要找出可以優化的地方**（11/24，矽晶圓-1、矽晶圓-2、光罩-1）
   - 原話：「影片不用全部重作，但要找出可以優化的部分進行」。
   - 以後：先看總覽圖，把簡陋、太空、太淡的段落列出來，只補那些段落，旁白和時間軸不動。
8. **每支影片都要評分**（11/24）
   - 原話：「以後每隻影片都需要評分」（看完四支審片評分 5.5–7.0 之後）。
   - 以後：每支影片在渲染前（前段完成、無聲抽格）和成片後各評一次分，都由沒參與製作的審片人打分，1–10 分，8 分以上才算專業知識影片。報告寫在 `docs/reviews/<日期>-<slug>.md`，列出必改、建議和各自交給誰。
   - 成片低於 8 分不准交給 Andy 當定稿，要先改到 8 分。交件和回報時第一行寫「評分：X／10（審片人）」。

## 審片反覆退件（開工就要避開，11/24 審片 4 支以上重複出現）
- 出處列只放真實資料來源（或「示意動畫，不是量測」），**不准放「下一集」「上一集」「series_plan」等預告或內部用語**。
- 片尾橘色橫條與所有卡片要在左右 64px 安全邊距內；橫條下方的小標不要重複橫條內容。
- 2D 卡上的 LOGO、國旗全程 100% 不透明（未輪到＝細灰框，輪到＝粗框＋放大），卡片退場 ≤4 幀，避免網格線穿過字。
- 標籤與圖釘不准壓 HUD 角標（層級名、倍率、FIELD、比例尺）；放在 y≈250–900。
- 念到公司或國家的那一刻畫面上就要有對應素材（廠房、廠牌、旗桿），不准空畫面；同類廠房外型要明顯不同。
- 鏡頭動作綁 cue id，不綁無聲估算秒數（配音後時間會移動）。
- 交審要附原尺寸單張（每秒一張或關鍵秒數 ≥12 張）＋每秒總覽，只給總覽審不準。

### 開場
10. **每支要接上一支，開頭 3 秒要有問句鉤子**（11/25，Andy：「每部影片應該是銜接上一部的，並且開頭為何沒有鉤子問法，需要補充上一個影片與這影片相關再進行三秒吸引，之後的都需要照規範」）
   - 原因：系列 2 各集各自開場（「晶片圖案，先畫在一層膠上」），沒講跟上一集的關係，也沒有問句；觀眾不知道為什麼要接著看。
   - 以後：第一幕旁白＝「上集〔上一集的結論或懸念〕＋這集的問題？」（3 秒內念到問號），接著才回答；第 0 幀大字標題上方的 kicker 寫「接上集：…」，標題本身是問句或數字。片尾預告下一集時，要留下一集開頭會接的那個點。
   - 擋：scripts/three/validate-three.mjs「開場銜接／開場鉤子」（script.prevEpisode 有填或 asOf ≥ 2026/11/25 一律 error；系列第一集寫 seriesFirst: true）。
   - 已套用：光罩-2、光阻-1、光阻-2（未配音的三支）。已配音的矽晶圓-1、矽晶圓-2、光罩-1 Andy 同意先通過。

   - 原話：「影片好了先給我」。
   - 以後：成片一渲染完就傳給 Andy，附目前的評分和已知問題，不必等成片審片或修正後的重渲。成片審片與修改照常進行，修好的版本再補傳。正式定稿仍要 8 分以上。

## 渲染太久（2026-11-24 Andy：「若是影片有些製作太久 超出平常一般影片製作時間，請確認原因被改善」）
- 事故：矽晶圓-1 v3 渲染超過 70 分鐘（平常 23～42 分）。原因：約 12:29 中斷的渲染遺留孤兒 headless Chrome（父程序已死、掛在 init 下），吃約 200% CPU 三小時；同時還有配音子 agent 在跑。
- 改善：`make-tech.sh` 渲染前在 flock 內跑 `scripts/three/render-guard.sh`（清孤兒 Chrome、印負載與前 5 名程序）；渲染記開始／結束與分鐘數，寫進 `out/render-times.tsv`；超過 `RENDER_WARN_MIN`（預設 60 分）自動印警告與當下吃 CPU 的程序。
- 規矩：渲染期間不跑配音、抽格、審片截圖等任何吃 CPU 的工作；渲染超過 60 分鐘先查負載與孤兒程序，不要只等。

## 2026-11-24 渲染程序卡住（②自查，非 Andy 指出）
- 經過：矽晶圓-2 渲染到 40% 時停掉 make-tech 要改 LOGO，但 `node scripts/render.mjs` 子程序沒被停掉，19:52 輸出後卡住不結束、一直握著 out/.render.lock；新一輪排隊 1 小時 20 分鐘沒開始，查進度只看到舊 log 的 100%。
- 以後：停渲染一律 `pkill -f "render.mjs <slug>"` 後再 `pgrep -fa render.mjs` 確認沒有；查進度先看 `ps -o etime=` 與 log 修改時間，對得上這一輪的開始時間才算數。
