# 科技透明圈：每日一支影片的製作手冊

範本片：`videos/tech-2nm/`（「兩奈米不是尺寸」，51.6 秒，使用者 2026/11/15 確認「影片非常棒」）。
新片照這支做。規則細節另見 `docs/channels/tech-3d.md`（18 條檢查清單）、`docs/three-stage.md`（3D 引擎與 HUD 寫法）、`docs/skills/3d-industry-explainer-video.md`。

## 一、每天的分工

| 步驟 | 誰做 | 產出 |
|---|---|---|
| 1 選題、查證 | 自動 | `research.md` |
| 2 寫腳本、建模型資料 | 自動 | `script.json`、`model.json` |
| 3 無聲預覽＋旁白提示詞 | 自動 | 九格圖、`docs/prompts/<slug>-旁白.txt` |
| **4 生成旁白並上傳** | **使用者手動** | 一個 wav 檔 |
| 5 接旁白、對時間、渲染 | 自動 | `out/<slug>.mp4`、字幕檔、九格圖 |
| 6 檢查、交片 | 自動，使用者看過才發布 | 成片＋已知問題清單 |

每天只有第 4 步要人：到 aistudio.google.com/generate-speech，模型 Gemini 2.5 Flash Preview TTS，單人模式，音色 **Iapetus**，Style instructions 貼「說明 B」，文字框貼當天念稿，下載 wav 上傳。不送 API 請求。

說明 B（固定，不改）：

    用台灣人平常講話的口音，不特別捲舌、不兒化，語氣溫和親切，像在跟一個好奇的朋友解說，問句自然上揚，講到答案時肯定一點，語速稍快、不拖尾音，直接說：

## 二、內容規格

- 片長 45–60 秒，18–20 鏡，旁白約 220–240 字，7 段左右。片尾卡 ≥3 秒（科技透明圈／一支講透一件事／下一支 ▸ 題目／留言「關鍵字」拿完整資料；可以用 `endCard.at` 提早到最後一句念到題目前開始）。
- 結構：
  1. 第 0 幀就有反差大字（例：「2奈米不是尺寸」）加一個已經在動的東西，1.5 秒內蓋章。
  2. 從日常物件一級一級放大（手機 → 主機板 → 晶片 → 單一零件），每一級一句旁白、停 2–3 秒，右上角標倍率。
  3. 3D 爆炸圖拆開，標零件名（中文大字＋英文小字）。
  4. 運作動畫：演「它實際怎麼動」，開與關、對與錯各一鏡，不擠在同一鏡。
  5. 一個對照或衝突（上一代對這一代）。
  6. 回答開頭的問題，給出數字。
  7. 拉回日常物件，講「對你的差別」。
  8. 具體提問／留言關鍵字＋下一支預告，片尾卡。
- 旁白寫法：短句、一句一件事、自問自答可以；不用中國用語與兒化；數字在念稿寫成唸法；同一個零件全片只用一個名字。
- 一幕畫面主要東西 ≤3 樣；小字下限 30px；標籤不壓到模型。

## 三、事實紀律

- 時事與數字一律上網查證，寫進 `research.md`，每個數字標來源與日期。
- 廠商公布的目標值要說是「廠商目標」，畫面標「非實測」；試作品的數字要標是哪個試作品。
- 畫面常駐「示意圖，非實際比例」；運作動畫的出處列寫「運作為示意」。儀表不標沒查證的數字，漏電之類的示意不畫成歸零。
- 不出現真實商標、不仿特定機型、不出現真人；公司名只放在出處小字。不給投資建議。

## 四、畫面與技術設定

- `styleVersion: 3`、`stage: "three"`，頻道字樣「科技透明圈」，`hudSkin` 選配色（主要風格 `light`：淺色底配藍色與橘色；`glass` 冰藍加萊姆綠留作備用；色票只改 `src/theme-hud-skins.json`）。
- `hud.layout: "fill"`（撐滿版面，見第九節）、`hud.smallPx: 30`；新片一律寫。
- 零件模型是資料（`model.json`），用基本形狀建，換題目不改引擎。新畫面優先用 2D 疊層（`props.overlay`），不增加 3D 成本。
- 3D 只掛在需要的鏡，前後的放大與拉回用 2D。這台機器沒有 GPU：畫布倍率 1、平行數 4，一支約 20 分鐘；開工前跑 `node scripts/three/bench30.mjs <slug>` 估時間，`df -h /` 確認空間 ≥1GB。
- 混音由 render 自動加背景音樂與轉場音效，目標約 −14 LUFS。

## 五、指令順序

    npm run validate <slug>                      # 0 error 才往下（含版面檢查 layout-check）
    node scripts/three/layout-check.mjs <slug>   # 只跑版面檢查（幾秒，不渲染）
    node scripts/ui/silent-timeline.mjs <slug>   # 無聲時間軸，先看畫面
    node scripts/v3/peek.mjs <slug> ...          # 抽看關鍵時刻
    # —— 等使用者上傳旁白 ——
    # 把錄音放到 public/audio/<slug>/ 的整篇快取位置後：
    node scripts/tts-take.mjs <slug> --resplit   # 只重切，不送請求
    node scripts/align.mjs <slug> --force        # 一定要 --force
    npm run render <slug>
    python3 scripts/v3/review-sheet.py <slug>
    python3 scripts/voice-retro.py ...           # 量語速與捲舌指標

- 不帶 `--resplit` 跑 `tts-take.mjs` 可能送出 API 請求，不要這樣跑。
- 接錄音的完整做法與備份方式見 `videos/tech-2nm/voice.md`。
- 錄音照原樣用：不加速、不壓句間停頓。錄音若含兩個版本，用強制對齊確認分界，不要只看靜音。

## 六、交片前檢查

- 旁白每一句都對得上、順序正確；對齊信心低於 0.5 的鏡請使用者聽。
- 每鏡至少 2 秒；蓋章、小標落定後至少停 0.8 秒；沒有黑幀；片長 45–60 秒。
- 前 3 秒每 2 幀、全片每 0.25 秒抽格看過。
- 回報要寫：片長、語速、捲舌指標（偏高要照實說）、已知問題、哪些沒檢查。
- 影片、音檔、圖片不進 git。

## 七、tech-2nm 留下的已知問題（新片要避開）

- 前 3 秒事件偏少，只有大字、蓋章與慢推。
- 主機板、晶片兩鏡停留時接近靜止超過 1.5 秒。
- 拉回手機時四級在 1.3 秒內閃過。
- 旁白比預期快時，部分鏡只剩約 2 秒、蓋章只停 0.8 秒：腳本每鏡至少留 12 個字。
- 片尾卡 2.4 秒偏短，建議 3 秒。

## 八、每日排程（建議）

- 前一天晚上：自動完成第 1–3 步，把念稿與九格圖交給使用者。
- 使用者上傳旁白後約 30 分鐘內交片。
- 題目清單先排一週，下一支的題目寫進前一支的片尾卡（tech-2nm 預告的是「曝光機」）。
- 每天花費：API 配音 0 次；自動步驟約 30–60 分鐘機器時間。

### 主素材不准被遮（固定規則）

Andy 2026/11/15 截了 s16 附近（「同樣效能」）的畫面：右上角 HUD 讀數（Schematic／示意圖，非實際比例／×1／FIELD 18 cm）壓在手機線稿上，「同樣效能下的耗電」橫條卡蓋住手機中段；IG 底部漸層蓋住出處那一行。原話：「避免中間重要的素材被遮擋」。

- **主素材框**：每一幀畫面中間的主體。2D 階段＝鏡頭現在對著的那一級圖（手機／主機板／晶片／陣列／一顆電晶體，外框在 `hudLayout.ts` 的 `ART_BOX`）；3D 階段＝模型投影的外接矩形（和算模型範圍同一個方法）。layout-check 逐幀算。
- **HUD 讀數集中在舞台上下兩條帶子**（`LAYOUT_3D_FILL.BAND_TOP`＝104、`BAND_BOTTOM`＝88）：上帶＝左層級名（手機／PHONE）、右倍率＋FIELD；下帶＝左尺標、右「Schematic – not to scale／示意圖，非實際比例」。2D 圖只畫在兩條帶子中間（`artRegion`），讀數物理上壓不到它；3D 模型若伸進帶子會被檢查抓到。
- **有東西要出現時主素材先讓位**（`planHud`／`makeYield`）：鉤子大字、對照卡、橫條卡、提問卡、儀表，以及找不到空位的蓋章與標籤，出現前約 20 幀主素材就開始縮小、移到剩下最大的空白（2D 圖與 3D 畫布同一個變形，±6 幀平滑），東西退場後再回來。卡片放在舞台下半（`y` 讓卡片下緣貼著 artRegion 下緣），主素材縮到上半。
- 蓋章與標籤先找不壓主素材、不壓讀數帶、不壓其他東西的空位（`freeSpot`）；真的沒有空位才留在原位、改成主素材讓位。
- 半透明退成背景只在「兩者真的不能並存」時才用；目前的做法是縮小移開，不需要半透明。
- 新片的卡片 `y`：對照卡／橫條卡／提問卡讓下緣在 y≈1242（artRegion 下緣）；鉤子大字放在 artRegion 上緣（tech-2nm `hook.top: 470`）。

### 留言關鍵字（固定規則）

Andy 2026/11/15：「往後製作影片後面可以補上 留言『XXXX』我就把資訊傳給他，IG Thread 都是」。

- 每支影片都要訂一個留言關鍵字：2～4 個字，跟題目有關（tech-2nm＝「2奈米」）。寫在 script.json 最後一幕的 `props.endCard.comment`。
- 念稿的最後一句要念出來，例如「想要完整資料，留言兩奈米」（念稿版數字寫成唸法；字幕照原文）。旁白是使用者錄的，所以寫稿時就要放進念稿交給他。
- 片尾卡顯示一行「留言「關鍵字」拿完整資料」：在「下一支 ▸」下方，46px（≥40），LOGO 落定後才出現（`ENDCARD.comment`），之後至少停 1 秒。
- `research.md` 的內容會整理成精選文章「科技透明圈」分頁的一篇文章。這個分頁是隱藏的，留言的人會收到文章連結；所以 research.md 要寫成能直接改成文章的樣子（每個數字附來源與日期、已確定／廠商目標／試作品分清楚）。
- layout-check 會檢查：有沒有寫 `comment`（沒寫出警告）、2～4 字、字級 ≥40、一行放得下、在片尾卡框內、LOGO 落定後才出現、出現後停 ≥1 秒。
- tech-2nm 例外：旁白早就錄好，最後一句沒有念關鍵字，只在片尾卡顯示；下一支起照規則念。

### 片尾 LOGO 動畫（固定規則）

使用者 2026/11/15：「Logo 需要符合頻道設計的含義去想」。開口圈 LOGO 的含義（tw-rotation `docs/brand/tc_logo_1102/README.md` 第 1 案）：一條開口的圓環＝「圈」，缺口那顆暖色小點＝「進來的你」。美術審查記過弱點：它有點像「重新整理／載入中」的圖示。所以動畫要演「圈子打開，你走進來」，而且不能有任何轉圈的感覺。

| 順序 | 動作 | 代表的意思 | tech-2nm 時間（片尾卡開始後） |
|---|---|---|---|
| 1 | 圓環從缺口對面（左下）同時往兩邊長，停在缺口兩端，缺口在定稿位置；**圓環整體不旋轉、不沿一個方向繞** | 圈子打開、留一個位置給你 | 第 2–18 幀（0.07–0.60 秒） |
| 2 | 橘點從缺口外側沿一條短弧線移過來（慢進慢出），穿過缺口落在定稿位置，沿進來的方向往圈內多走一點再回來（小回彈）；**不是從上面掉下來** | 你走進來 | 第 14–27 幀落定（0.47–0.90 秒），回彈到約第 33 幀 |
| 3 | 落定那一刻圓環回應一次：線條微微變粗再恢復，加一圈淡色細線往外擴 | 圈子接住了你 | 第 27–39 幀（0.90–1.30 秒） |
| 4 | 頻道名 → 底線 → slogan → 軌跡（手機／主機板／晶片／電晶體）依序進場 | — | 第 30–53 幀（1.00–1.77 秒） |
| 5 | 「下一支 ▸ 題目」等 LOGO 落定之後才出現（不搶在 LOGO 前面，晚於旁白念到題目也可以） | — | 第 52–64 幀（1.73–2.13 秒）；比旁白念到「曝光機」晚 40 幀 |
| 5b | 「留言「關鍵字」拿完整資料」在「下一支」下方出現 | 看完要怎麼拿到完整資料 | 第 56–64 幀（1.87–2.13 秒） |
| 6 | 全部落定後停住 ≥1 秒 | — | 第 64–95 幀（約 1.03 秒） |

- 時間表在 `src/components/three/hudLayout.ts` 的 `ENDCARD`，畫法在 `Hud.tsx` 的 `HudMark`／`dotPath`／`HudEndCard`；頁首的小 LOGO 永遠是定稿的靜態樣子。
- 禁止：圓環旋轉、繞圈描線（一個端點沿圓周跑一整圈）、點繞著圓環轉、霓虹發光、讓「下一支」比 LOGO 先出現。

小細節（每次交片前看一遍）：
