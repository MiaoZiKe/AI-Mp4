# 科技透明圈：每日一支影片的製作手冊

範本片：`videos/tech-2nm/`（「兩奈米不是尺寸」，51.6 秒，使用者 2026/11/15 確認「影片非常棒」）。
新片照這支做。規則細節另見 `docs/channels/tech-3d.md`（18 條檢查清單）、`docs/three-stage.md`（3D 引擎與 HUD 寫法）、`docs/skills/3d-industry-explainer-video.md`。

## 一、每天的分工

| 步驟 | 誰做 | 產出 |
|---|---|---|
| 1 選題、查證 | 自動 | `research.md` |
| 2 寫腳本、建模型資料 | 自動 | `script.json`、`model.json` |
| 3 無聲預覽＋旁白提示詞 | 自動 | 九格圖、`docs/prompts/<slug>-旁白.txt` |
| **4 生成旁白並上傳** | **使用者手動** | 一個 wav 檔 |
| 5 接旁白、對時間、渲染 | 自動 | `out/<slug>.mp4`、字幕檔、九格圖 |
| 6 檢查、交片 | 自動，使用者看過才發布 | 成片＋已知問題清單 |

每天只有第 4 步要人：到 aistudio.google.com/generate-speech，模型 Gemini 2.5 Flash Preview TTS，單人模式，音色 **Iapetus**，Style instructions 貼「說明 B」，文字框貼當天念稿，下載 wav 上傳。不送 API 請求。

說明 B（固定，不改）：

    用台灣人平常講話的口音，不特別捲舌、不兒化，語氣溫和親切，像在跟一個好奇的朋友解說，問句自然上揚，講到答案時肯定一點，語速稍快、不拖尾音，直接說：

## 二、內容規格

- 片長 45–60 秒，18–20 鏡，旁白約 220–240 字，7 段左右。最後一鏡是 2.4 秒以上的無聲片尾卡（科技透明圈／一支講透一件事／下一支 ▸ 題目）。
- 結構：
  1. 第 0 幀就有反差大字（例：「2奈米不是尺寸」）加一個已經在動的東西，1.5 秒內蓋章。
  2. 從日常物件一級一級放大（手機 → 主機板 → 晶片 → 單一零件），每一級一句旁白、停 2–3 秒，右上角標倍率。
  3. 3D 爆炸圖拆開，標零件名（中文大字＋英文小字）。
  4. 運作動畫：演「它實際怎麼動」，開與關、對與錯各一鏡，不擠在同一鏡。
  5. 一個對照或衝突（上一代對這一代）。
  6. 回答開頭的問題，給出數字。
  7. 拉回日常物件，講「對你的差別」。
  8. 具體提問或下一支預告，片尾卡。
- 旁白寫法：短句、一句一件事、自問自答可以；不用中國用語與兒化；數字在念稿寫成唸法；同一個零件全片只用一個名字。
- 一幕畫面主要東西 ≤3 樣；小字下限 30px；標籤不壓到模型。

## 三、事實紀律

- 時事與數字一律上網查證，寫進 `research.md`，每個數字標來源與日期。
- 廠商公布的目標值要說是「廠商目標」，畫面標「非實測」；試作品的數字要標是哪個試作品。
- 畫面常駐「示意圖，非實際比例」；運作動畫的出處列寫「運作為示意」。儀表不標沒查證的數字，漏電之類的示意不畫成歸零。
- 不出現真實商標、不仿特定機型、不出現真人；公司名只放在出處小字。不給投資建議。

## 四、畫面與技術設定

- `styleVersion: 3`、`stage: "three"`，頻道字樣「科技透明圈」，`hudSkin` 選配色：**`light`**（使用者 2026/11/15 定案＝頻道貼文風：淺藍白底、亮藍 #1F6FEB、橘 #FF9F1C、深藍字、開口圈標誌）；`glass`／`brand` 留著備用。色票只改 `src/theme-hud-skins.json`。
- 零件模型是資料（`model.json`），用基本形狀建，換題目不改引擎。新畫面優先用 2D 疊層（`props.overlay`），不增加 3D 成本。
- 3D 只掛在需要的鏡，前後的放大與拉回用 2D。這台機器沒有 GPU：畫布倍率 1、平行數 4，一支約 20 分鐘；開工前跑 `node scripts/three/bench30.mjs <slug>` 估時間，`df -h /` 確認空間 ≥1GB。
- 混音由 render 自動加背景音樂與轉場音效，目標約 −14 LUFS。

## 使用者 2026/11/15 修正（之後每支都要照做）

使用者看完 tech-2nm（light 版）提出，並說之後每支科技片都照做。第一支照做的是 `videos/tech-2nm/`（成片 `out/tech-2nm.light-v2.mp4`）。

1. **LOGO 固定在左上角、版面不要留大片空白。** 版面數值在 `src/theme.ts` 的 `LAYOUT_HUD`（只給 HUD 片用，舊的 `LAYOUT_3D` 3D 片不受影響）：頁首 100–164（開口圈＋頻道名，全片不動，片尾卡也蓋在它下面）、舞台 184–1404（高 1220，舊版 300–1290；舞台中心幾乎不變，所以疊層 y 不用改，3D 模型自然放大約 1.23 倍）、字幕 1420–1656、出處 1676、1724–1920 頻道色帶（淡底＋滑動刻度＋全片進度條，不放要讀的字）。新片不要自己另訂版面。
2. **片尾卡的 LOGO 要有動畫。** `Hud.tsx` 的 `RingMarkAnim`：圓弧描線畫出（2–20 幀）→ 橘點繞圓心轉進缺口、落定回彈（16–34 幀）→ 一圈脈衝往外擴（34–52 幀）→ 頻道名、slogan、路線、下一支依序出現 → 之後輕微呼吸。片尾卡 `durationSec` 用 3 秒。
3. **物理／運作效果要清楚、有方向、跟旁白同步。** 電流用 `model.json` 的 `actions` 新 type `stream`（2D 畫在 3D 投影位置上，幾乎不增加渲染成本）：`lanes` 多條源極→汲極路徑、每條 `n` 顆電子（實心點＋往後拖的尾巴）、`drive` 指向閘極電壓動作，速度跟著電壓——加電壓逐漸加速、拿掉電壓減速後停住再淡出；`field` 畫閘極到各片的流動電場線；閘極的 `pulse` 加 `stagger` 讓幾塊零件依序亮起（充電掃過感）。舊架構對照的漏電小點不能畫成零。出處列照舊寫「示意」。

## 五、指令順序

    npm run validate <slug>                      # 0 error 才往下
    node scripts/ui/silent-timeline.mjs <slug>   # 無聲時間軸，先看畫面
    node scripts/v3/peek.mjs <slug> ...          # 抽看關鍵時刻
    # —— 等使用者上傳旁白 ——
    # 把錄音放到 public/audio/<slug>/ 的整篇快取位置後：
    node scripts/tts-take.mjs <slug> --resplit   # 只重切，不送請求
    node scripts/align.mjs <slug> --force        # 一定要 --force
    npm run render <slug>
    python3 scripts/v3/review-sheet.py <slug>
    python3 scripts/voice-retro.py ...           # 量語速與捲舌指標

- 不帶 `--resplit` 跑 `tts-take.mjs` 可能送出 API 請求，不要這樣跑。
- 接錄音的完整做法與備份方式見 `videos/tech-2nm/voice.md`。
- 錄音照原樣用：不加速、不壓句間停頓。錄音若含兩個版本，用強制對齊確認分界，不要只看靜音。

## 六、交片前檢查

- 旁白每一句都對得上、順序正確；對齊信心低於 0.5 的鏡請使用者聽。
- 每鏡至少 2 秒；蓋章、小標落定後至少停 0.8 秒；沒有黑幀；片長 45–60 秒。
- 前 3 秒每 2 幀、全片每 0.25 秒抽格看過。
- 回報要寫：片長、語速、捲舌指標（偏高要照實說）、已知問題、哪些沒檢查。
- 影片、音檔、圖片不進 git。

## 七、tech-2nm 留下的已知問題（新片要避開）

- 前 3 秒事件偏少，只有大字、蓋章與慢推。
- 主機板、晶片兩鏡停留時接近靜止超過 1.5 秒。
- 拉回手機時四級在 1.3 秒內閃過。
- 旁白比預期快時，部分鏡只剩約 2 秒、蓋章只停 0.8 秒：腳本每鏡至少留 12 個字。
- 片尾卡 2.4 秒偏短，建議 3 秒。

## 八、每日排程（建議）

- 前一天晚上：自動完成第 1–3 步，把念稿與九格圖交給使用者。
- 使用者上傳旁白後約 30 分鐘內交片。
- 題目清單先排一週，下一支的題目寫進前一支的片尾卡（tech-2nm 預告的是「曝光機」）。
- 每天花費：API 配音 0 次；自動步驟約 30–60 分鐘機器時間。
