## 一、每天的分工

| 步驟 | 誰做 | 產出 |
|---|---|---|
| 1 選題、查證 | 自動 | `research.md` |
| 2 寫腳本、建模型資料 | 自動 | `script.json`、`model.json` |
| 3 無聲預覽＋旁白提示詞 | 自動 | 九格圖、`docs/prompts/<slug>-旁白.txt` |

## 二、內容規格

> **內容邏輯（2026/11/15 起，四個頻道共用）**：照 tw-rotation 的 `docs/marketing/channels/video_logic.md`：開頭 3 秒抓住目光 → 有邏輯的介紹 → 吊人胃口的結尾；每句過四個檢查；交件附「自查五項」結果。範本片 `videos/liguligu-jensen-pro/`。
> 片長依本手冊（45–60 秒）；共用邏輯的三段時間點等比放大，鉤子仍是前 3 秒（頻道① 主控 11-15 定案）。

- 片長 45–60 秒，18–20 鏡，旁白約 220–240 字，7 段左右。片尾卡 ≥3 秒（科技透明圈／一支講透一件事／下一支 ▸ 題目／留言「關鍵字」拿完整資料；可以用 `endCard.at` 提早到最後一句念到題目前開始）。
- 結構：
  1. 第 0 幀就有反差大字（例：「2奈米不是尺寸」）加一個已經在動的東西，1.5 秒內蓋章。
  2. 從日常物件一級一級放大（手機 → 主機板 → 晶片 → 單一零件），每一級一句旁白、停 2–3 秒，右上角標倍率。
  3. 3D 爆炸圖拆開，標零件名（中文大字＋英文小字）。
  4. 運作動畫：演「它實際怎麼動」，開與關、對與錯各一鏡，不擠在同一鏡。
  5. 一個對照或衝突（上一代對這一代）。
  6. 回答開頭的問題，給出數字。
  7. 拉回日常物件，講「對你的差別」。
  8. 具體提問／留言關鍵字＋下一支預告，片尾卡。
- 旁白寫法：短句、一句一件事、自問自答可以；不用中國用語與兒化；數字在念稿寫成唸法；同一個零件全片只用一個名字。
- 一幕畫面主要東西 ≤3 樣；小字下限 30px；標籤不壓到模型。

## 三、事實紀律

- 時事與數字一律上網查證，寫進 `research.md`，每個數字標來源與日期。
- 廠商公布的目標值要說是「廠商目標」，畫面標「非實測」；試作品的數字要標是哪個試作品。
- 畫面常駐「示意圖，非實際比例」；運作動畫的出處列寫「運作為示意」。儀表不標沒查證的數字，漏電之類的示意不畫成歸零。
- 不出現真實商標、不仿特定機型、不出現真人；公司名只放在出處小字。不給投資建議。

## 四、畫面與技術設定

- `styleVersion: 3`、`stage: "three"`，頻道字樣「科技透明圈」，`hudSkin` 選配色（主要風格 `light`：淺色底配藍色與橘色；`glass` 冰藍加萊姆綠留作備用；色票只改 `src/theme-hud-skins.json`）。
- `hud.layout: "fill"`（撐滿版面，見第九節）、`hud.smallPx: 30`；新片一律寫。
- 零件模型是資料（`model.json`），用基本形狀建，換題目不改引擎。新畫面優先用 2D 疊層（`props.overlay`），不增加 3D 成本。
- 3D 只掛在需要的鏡，前後的放大與拉回用 2D。這台機器沒有 GPU：畫布倍率 1、平行數 4，一支約 20 分鐘；開工前跑 `node scripts/three/bench30.mjs <slug>` 估時間，`df -h /` 確認空間 ≥1GB。
- 混音由 render 自動加背景音樂與轉場音效，目標約 −14 LUFS。

## 五、指令順序

    npm run validate <slug>                      # 0 error 才往下（含版面檢查 layout-check）
    node scripts/three/layout-check.mjs <slug>   # 只跑版面檢查（幾秒，不渲染）
    node scripts/ui/silent-timeline.mjs <slug>   # 無聲時間軸，先看畫面
    node scripts/v3/peek.mjs <slug> ...          # 抽看關鍵時刻
    # —— 等使用者上傳旁白 ——
    # 把錄音放到 public/audio/<slug>/ 的整篇快取位置後：
    node scripts/tts-take.mjs <slug> --resplit   # 只重切，不送請求
    node scripts/align.mjs <slug> --force        # 一定要 --force
    npm run render <slug>
    python3 scripts/v3/review-sheet.py <slug>
    python3 scripts/voice-retro.py ...           # 量語速與捲舌指標

- 不帶 `--resplit` 跑 `tts-take.mjs` 可能送出 API 請求，不要這樣跑。
- 接錄音的完整做法與備份方式見 `videos/tech-2nm/voice.md`。
- 錄音照原樣用：不加速、不壓句間停頓。錄音若含兩個版本，用強制對齊確認分界，不要只看靜音。

## 六、交片前檢查

- 旁白每一句都對得上、順序正確；對齊信心低於 0.5 的鏡請使用者聽。
- 每鏡至少 2 秒；蓋章、小標落定後至少停 0.8 秒；沒有黑幀；片長 45–60 秒。
- 前 3 秒每 2 幀、全片每 0.25 秒抽格看過。
- 回報要寫：片長、語速、捲舌指標（偏高要照實說）、已知問題、哪些沒檢查。
- 影片、音檔、圖片不進 git。

## 七、tech-2nm 留下的已知問題（新片要避開）

- 前 3 秒事件偏少，只有大字、蓋章與慢推。
- 主機板、晶片兩鏡停留時接近靜止超過 1.5 秒。
- 拉回手機時四級在 1.3 秒內閃過。
- 旁白比預期快時，部分鏡只剩約 2 秒、蓋章只停 0.8 秒：腳本每鏡至少留 12 個字。
- 片尾卡 2.4 秒偏短，建議 3 秒。

## 八、每日排程（建議）

- 前一天晚上：自動完成第 1–3 步，把念稿與九格圖交給使用者。
- 使用者上傳旁白後約 30 分鐘內交片。
- 題目清單先排一週，下一支的題目寫進前一支的片尾卡（tech-2nm 預告的是「曝光機」）。
- 每天花費：API 配音 0 次；自動步驟約 30–60 分鐘機器時間。

## 十、敘述邏輯（照哩股哩股，科技頻道版）

Andy 2026/11/16：「影片內容需要按照哩股哩股的敘述……若不知道請去問他需要注意什麼」。來源：tw-rotation `docs/marketing/channels/video_logic.md`＋主控 11-16 回覆（哩股哩股最新版在分支 `claude/nifty-goodall-syke8a` 的 `docs/channels/liguligu-daily-playbook.md`、`liguligu.md`、範本 `videos/liguligu-jensen-pro/`）。

## 十一、選題要串成一條鏈（上下游關聯＋往外延伸）

Andy 2026/11/16：「科技影片盡量都會有上下關聯性，或是具有拓展，舉例來說你介紹 IC 設計就延伸能介紹晶圓代工，晶圓代工可能又能介紹很多，包含 Vendor 商有誰、不同 Vendor 做什麼、代工哪些流程等等」。

- **每支片都要接得上一支、也要開得出下一支**：片尾預告的「下一支」就是這條鏈的下一個節點（上游、下游，或同一節點往下拆一層）。不准跳到沒有關聯的題目。
- **兩種走法輪流用**：
  1. 沿供應鏈走（上下游）：IC 設計 → 晶圓代工 → 設備（曝光、蝕刻、沉積、量測）→ 材料（光阻、矽晶圓、特用氣體）→ 封測 → 先進封裝 → 載板／PCB → 伺服器與系統廠。
  2. 同一節點往下拆（拓展）：例如晶圓代工 → 有哪幾家、各家做什麼不同 → 一片晶圓要經過哪些流程 → 每個流程用什麼設備、誰做的。
- **講 Vendor（廠商）**：可以點名公司、講它做什麼、市占或公開數字（附出處、標狀態）；不給投資建議、不點名推薦個股、不放公司商標圖案。
- **題目樹**寫在 tw-rotation `docs/marketing/channels/tc/topic_tree.md`（頻道 CEO 編輯維護）：每個節點標「已發／排程中／待做」與上一支、下一支是誰；每週一檢討會從樹上排下週 7 支科技拆解。
- 目前的鏈：兩奈米（製程世代）→ 曝光機（設備）→ 晶圓良率（製造）→ 先進封裝（後段）→ …

## 旁白基準：曝光機（2026/11/16 Andy：「曝光機的旁白…這聲音比較適合這頻道，以後都要是這旁白」）

- 曝光機怎麼呼叫的（以後每支照抄，不准改）：`NODE_USE_ENV_PROXY=1 node scripts/tts-take.mjs <slug>`；script.json `voice` ＝ `{ voiceName: "Iapetus", model: "gemini-2.5-flash-preview-tts", mode: "take", languageCode: "cmn-TW", profile: "tech-b" }`；提示＝`scripts/voice-profile.mjs` 的 `TECH_B_LINE`（「用台灣人平常講話的口音，不特別捲舌、不兒化，語氣溫和親切，像在跟一個好奇的朋友解說，問句自然上揚，講到答案時肯定一點，語速稍快、不拖尾音，直接說：」）＋念稿全文，整篇 1 次請求；生成後整篇 atempo 到純說話約 5.46 字／秒。
- 基準音檔：`public/audio/tech-euv/.take-3a5f783c6c.raw.orig.wav`（原始）。量測：原始純說話 4.43 字／秒、音高中位數約 116 Hz（10%–90%：86–173 Hz）。
- 同樣的設定，Gemini 每次生成的語氣與快慢還是會變（良率第 3 次只有 3.87 字／秒）。所以每次配音後先比基準：① 原始語速 4.3–5.0 字／秒 ② 音高中位數 110–125 Hz、90% 位數 ≤185 Hz。不合就重配（同一份念稿，每支最多再 2 次），合的才渲染；並剪「曝光機 12 秒＋嗶＋新片 12 秒」給 Andy 聽。
- 送 API 前逐句檢查念稿（lessons #35）：沒有「欸」、句子不以英文字母開頭、AI 不拆字母、數字單位念法對。

## 每支都要有（2026/11/16 Andy 看完先進封裝 v1：「補充是哪些公司在做」「影片的語氣需要適當停頓不要太急促」）

- 「哪些公司在做」：每支在講完原理之後加 1 段（2～3 句旁白＋一張名單卡）：做這件事的主要公司與技術名、台灣相關供應鏈（有來源才放）。狀態標籤分清楚：公司官方＝已確定、市場報導／估計＝媒體報導（標誰報的）；不寫客戶占比數字除非有一手來源；不給投資建議。查證派 semi-chain-analyst／pcb-substrate-analyst／ai-server-analyst，寫進該片 research.md。
- 停頓：段落之間 `pauseAfter` 0.6～0.8 秒、句子之間 ≥0.3 秒；說話本身仍照曝光機語速；總長 45～60 秒，超過就刪句，不壓停頓。

## 運作原理要畫得細、畫得生動（2026/11/17 Andy 看完先進封裝 v2：「往後的影片在素材的細緻度，還有它的設備上的運作原理，我需要再補充詳細一點，描繪的生動一點，這樣讓讀者可以更直觀知道你在幹嘛」）

- device-spec 先寫「每一步實際怎麼動」：哪個零件、往哪個方向、先後順序、力或能量從哪來，每一步對到一句旁白與一個畫面。
- 每支至少 3 段跟旁白同步的運作動畫（原本 2 段），最關鍵那段加放大特寫＋2D 剖面。
- 零件照真實形狀、比例、材質做，加標註；少用方塊、不留空背景。
- mechanical-engineer 交件前逐步核對「只看畫面也懂在幹嘛」；評分的素材貼近度、畫面品質照這條扣分。

## 節奏、公司引線、細緻度（2026/11/17 Andy 看完伺服器 v1：「影片動畫有點急促，沒有太多時間給讀者看……沒查到、不知道的事情就不用再特別說明，沒意義……哪間公司做什麼，可以用線條的方式拉出來……電路板和其他元件、設備、運作過程等細緻程度不夠好，要再加強」）
1. **不急促**：每個畫面（字卡、標籤、疊層）落定後至少停 1.5～2 秒才換下一個；一幕事件太多就刪字或拆幕，不准為了塞進片長加快動畫。
2. **公司卡只列查到的**：有來源才寫；查不到、不確定的公司或部位直接不寫，不出現「尚未確定／查不到」這類說明。
3. **公司用引線指部位**：從公司名拉線到 3D 模型上它負責的零件（`labels`／overlay 引線），讓觀眾一眼看到「誰做哪裡」；文字表格只能當補充。
4. **細緻度**：電路板（走線、元件、接頭）、設備內部零件要做出細節；運作過程（電流、資料、水流、氣流、機械動作）要逐步、有方向、跟旁白同步，搭近景＋2D 剖面。
交件前用格子圖逐條自查這四點，不合格不送 Andy。
5. **畫面與旁白逐句對上**（Andy 同日：「內容、素材與旁白對不上，這點請修正，避免往後發生」）：念到哪個零件／公司／數字，同一刻（cue ±0.3 秒）畫面就出現或指到它；每句字幕都有自己的畫面事件，不准一張卡撐好幾句不同內容。交件前從 storyboard.json 產「逐句念稿 ↔ 該時刻畫面」對照表（附該幀截圖），全部對上才送。
