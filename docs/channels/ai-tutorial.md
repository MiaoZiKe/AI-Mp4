# AI 教學頻道規則（腳本與畫面檢查用）

使用者 2026/11/13 的決定：「回答的文字是真的，介面仍然自己畫，用文字寫出工具名稱和測試日期。不碰真實商標。」「需要搭配新聞、時事這類主題。」先前也說旁白「太演講感、有點 AI，需要更像真人」。
第一支照這份規則做的正式片：`videos/sample-ai-news/`（20 鏡、約 65–70 秒；一開始做過 20 秒試片，後來使用者說「影片需要完整」，擴寫成完整版）。背景研究：`../ai-tutorial-viral-formats.md`；講話像不像真人：`../voice-natural.md`。

## 1. 題目：一則新聞配一招

1. 每支片從一則**台灣觀眾這幾天有感的新聞**開始（物價、薪資、房租、交通、科技產品、選務日程），教「用 AI 處理這則新聞」的一招。一支只教一招。
2. 常用角度：長新聞請 AI 抓重點又不亂講；請 AI 分出「已確定／還不確定」；請 AI 用自己的處境解讀；請 AI 把兩篇說法不同的報導並排。
3. 新聞事實一律上網查證，寫進該片 `research.md`：來源、公布日期、查證日期、已確定／分析預期／尚未確定。沒讀到原文就照實寫。
4. 選題時先列 3 個候選並寫下不選的理由。避開：只有單一來源的消息、個股漲跌、要對多位候選人逐一公平的選舉題材。政治題材保持中立，不給投資建議。
5. 新聞只是引子，片子不評論新聞本身（不說物價高不高、誰對誰錯）。

## 2. 回答必須是實測

1. 片中出現的 AI 回答都是**真的送出去、真的回來的**。「隨便問」和「這樣問」各送一次，同一個工具、同一個模型、同一天。
2. 每次實測存檔：`videos/<slug>/tests/*.json`（提示、模型名稱與回應回報的版本、送出時間、完整原始回答）與 `tests.md`（對照查證的逐點檢查）。
3. 回答**不能改寫**。畫面放不下只能刪節，並標「（節錄）」；可以拿掉粗體記號和項目符號，字不能動。
4. 畫面上用文字寫出工具名稱與測試日期（例：「Gemini｜2026/11/13 實測」），旁白講一次「我們拿 ○○ 實測」。
5. 照實講測試條件：是 App 還是 API、有沒有開搜尋、測了幾次。只測一次就不說「都會這樣」。「隨便問」建議再送一次看穩不穩定，第二次的回答另外存檔（不蓋掉第一次），兩次不一樣就照實講。
6. 好提示的回答如果也有錯，照實記在 `tests.md`，換一個角度，或直接在片中點出「AI 也會錯，要對原文」。不能為了好看重測到滿意為止卻不講。
7. 貼給 AI 的新聞文字用自己整理的一段（註明是自己整理的），不整篇照貼媒體原文。

## 3. 介面自己畫，不碰商標

1. 畫面是自製的仿介面（`stage: "ui"`，`src/components/ui/`）：視窗、游標、頭像、圖示都自己畫。
2. 不出現真實產品的商標圖案、介面截圖、配色與版面的仿製；工具名稱只用文字寫。不出現真人肖像。不加 AI 標示。
3. 正式片的骨架（45–75 秒、旁白 250–290 字、18–24 鏡、每鏡 2–4 秒）：
   起：大字鉤子帶新聞 → 隨便問。
   承：真的回答被紅筆圈出問題 → 為什麼會這樣（照實講測試條件）。
   轉：這樣問的寫法一塊一塊出現 → 真的回答分幾鏡看 → 上下並排對照（兩個回答同時停至少 1.5 秒）→ 提醒「AI 也會錯，要對原文」（最好用這次實測裡真的出現的問題當例子）。
   合：可截圖的範本卡 → 具體提問 → 一句下一集的問題 → 片尾卡（無聲約 3 秒）。
   script.json 頂層寫 `sample: false`，最後一幕 `silent: true`＋`durationSec`＋`props.endCard`；validate 會檢查。10–20 秒的風格試片不寫 `sample: false`。
4. 借來的手法各有上限：開頭大字 1 次（第 0 幀就是實心完整的字）；紅筆圈 1 次、打勾 1 次；上下對照 1 次。不整支做成大字片或手繪片。
5. 每鏡只留一個會動的重點。打字有快慢和停頓。

## 4. 旁白：像跟朋友講

1. 照 `../voice-natural.md` 第八節「親和專業」（使用者 2026/11/13 看完完整片的意見：旁白不要太輕浮，要親和專業）：像懂行又好相處的前輩在解釋。不用欸、蛤、齁、耶、嘛、啦；用其實、所以、你會發現、我們來看這類連接；句尾的喔、呢全片最多一兩個；句子完整但不書面，長短句交錯，不用冒號、不排比。
2. 一定要有：一句帶到新聞的開頭、一句「我們拿 ○○ 實測」、一句提醒 AI 也會錯要對原文、結尾一個具體提問（不寫「分享給／傳給／標記」）、最後一句下一集要講什麼（下一集還沒做實測就只能用問句，不能先講結論）。
3. 口語化不能改事實：年份不對就說年份不對，不說「亂編」；「更準」只能指「和貼的原文一致」。
4. 設定：Sulafat、`gemini-2.5-flash-preview-tts`、`mode: "take"`、`cmn-TW`；`voice.profile` 用 `ai` 預設（已內建 `delivery: "warm-pro"` 與茶水間場景）。要短就刪字，不壓停頓。

## 5. 片尾範本卡

1. 片尾前放一張可以照抄的提示範本卡，內容就是這支片實測用的寫法，把個人處境留成空格。
2. 停留夠久可以截圖（至少 2 秒），字要在手機上看得清楚。
3. 貼文說明附純文字版範本、兩個提示全文、工具與模型版本、測試日期與條件、新聞出處。
4. 要用「留言關鍵字拿範本」之前，先確定真的有人會回覆。

## 6. 交付前逐條對

- [ ] 新聞數字和 `research.md` 一致，未定的有標日期
- [ ] 畫面上的回答和 `tests/*.json` 逐字相同（節錄有標）
- [ ] 有工具名稱、測試日期；沒有商標、截圖、真人
- [ ] 旁白有「我們實測」、有「對原文」的提醒，結尾是提問加下一集的問題；最後一幕是片尾卡
- [ ] 對照鏡兩個回答同時停滿 1.5 秒；範本卡看得清楚
- [ ] 每支片有只有這一支才有的實測內容，不是同一個模板換字
