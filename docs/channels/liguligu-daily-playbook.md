# 哩股哩股：追問式短片的製作手冊

範本片：`videos/liguligu-jensen-pro/`（「33 年執行長，辭職即刻生效」，23.4 秒，使用者 2026/11/15 確認 OK）。
新片照這支做。規則全文另見 `docs/channels/liguligu.md`；這支片的每鏡內容、指令與已知問題見 `videos/liguligu-jensen-pro/README.md`，旁白做法見同資料夾的 `voice.md`。


## 零、標準流程（使用者 2026/11/15：「以後都是 找題材 規劃 生成 驗證 優化 配上旁白 就發布；先生成影片驗證錯誤，確認 OK 再進行旁白配音，最後再驗證才發布；並每週檢討」）

1. **找題材**：至少兩個獨立來源核對；有「對不上的地方」才做（第二節）。原文讀不到的句子在 research.md 標「只看到摘要」。可用 YouTube 逐字稿找題材，但 YouTuber 的說法一律算「分析推測」。
2. **規劃**：先寫一句話主旨（15–25 字），再寫追問結構＋念稿最終版（最後一句念留言關鍵字），交給主控。寫稿照 tw-rotation `docs/marketing/channels/video_logic.md` 第六節八條（使用者 2026/11/16）：開頭先交代情境再丟反常事實；30 秒數字 ≤3、事實 ≤4；每句回答上一句的問題；沒介紹過的代名詞與專有名詞不出現；寧可砍事實不加快語速（約 110–130 字／30 秒）；結尾只留一個動作（提問改放貼文文案）；只聽旁白能講回主旨才算過。交件附「主旨一句＋八條自檢」。script.json 頂層寫 `thesis`。
3. **生成無旁白影片**：無聲估算時間軸 → 渲染 → 片尾招牌音合進去。
4. **驗證**（每一項都要過）：
   - 版面：`python3 scripts/dossier/edge-check.py <slug>`，上下留白 ≤60px；字幕卡下緣 ≤1700
   - 重疊：換鏡兩卡不半透明疊在一起；標籤／蓋章不壓主素材中央（抽格看）
   - 小字 ≥30px（填滿版出處、跑馬燈、地名都是 30px）
   - 靜止段 ≤1.2 秒：`node scripts/dossier/events.mjs <slug>`，內容鏡最大間隔 ≤1.2 秒（片尾卡落定後的停留不算）
   - 片尾 LOGO 淨空：片尾卡上沒有其他東西蓋到字標
   - **禁止事項**（使用者 2026/11/15，各頻道共用）：不要整張圖慢慢放大（填滿版已關掉整鏡慢推與照片慢推，改用物件本身的動作）；不用手繪圈（用細紅框、差距括號或螢光底）
5. **優化到通過**，用 Artifact 發預覽給主控／使用者看，**使用者說 OK 才配旁白**。
6. **配旁白**：**2026/11/15 起改用 API 生成**（使用者：「這邊通過了 可以以後呼叫API 生成旁白」）。Gemini TTS，模型 gemini-3.8-flash-tts（失敗才改 2.5），男聲，音色＝**Charon**（2026/11/15 比對 11/14 參考旁白：gemini-3.8-flash-tts 的 Charon 說話人相似度 0.903，其他候選 ≤0.835；`scripts/dossier/voice-match.py`，比對頁 https://claude.ai/artifact/LLNJbmNYjGDKchfbqtZa8D；使用者 11/15：「以後都是這旁白」；Iapetus、Achird 不用）。Node 送請求要加 `NODE_USE_ENV_PROXY=1`（不然不走代理、金鑰不會帶入）。免費額度每個模型每天 10 次、每分鐘 3 次，和其他頻道共用；說明句用 `docs/prompts/liguligu-男聲試聽-短說明.txt` 那一句。整篇一次生成（每支 1 次請求），模型把說明句也念出來時用逐字時間戳切掉、不切到第一個字的起音；之後 `recording-timeline.mjs` 接時間軸。金鑰由代理帶入，不寫進檔案。
7. **最後驗證**：每句都有、只念一遍、和念稿一致；起音不被切掉；字幕和聲音同步；正片旁白 −16 LUFS、片尾段約 −11.5 LUFS、真峰值 ≤ −1 dBTP（AAC 後量）。
8. **發布**：IG Reels＋Threads 影片，同時把 article.json 存成網站隱藏文章（發布路徑由主控安排）。發布前時事重查、「查證截至」改成發布日。
9. **每週檢討**：整理這週每支的問題與使用者意見，討論改善方向，更新這份手冊。

- **送 TTS 前必做**（使用者 2026/11/16，所有有配音的頻道：「開頭有點奇怪 不用"欸" AI的 "A" 也不見了 請確實在使用API前先確認內文有沒有錯誤再發送」；起因：念稿句首寫「A I」被念成「欸」）：① 每幕 `tts` 全文逐句印出來檢查，不准有「欸」這類多餘語助詞、不准錯字，數字與單位念法要對；② 句子不准用英文字母開頭，AI 直接寫「AI」，不拆成「A I」（句首要提 AI 就先放中文字，例如「現在 AI…」）；③ 確認沒問題才送 API，最終送出的 tts 全文留在交件紀錄（`videos/<slug>/voice.md`）；④ 成片交件前用耳朵聽前 5 秒（本機沒有耳朵時：用聽寫模型逐字轉寫前 5 秒，並在交件頁請 Andy 聽）。

## 二、題材與結構

- 題材：國際情勢、國際大公司與市場、基金。要有國際觀，不是單純介紹。
- 短片 20–30 秒、7 鏡左右、旁白約 110 字；完整片 45–75 秒，最後加片尾卡。
- 結構是追問，不是介紹：
  1. 前 3 秒丟出反常的事實或疑點：第 0 幀就是實心大字加數字，1 秒內有一個蓋章或框選動作。
  2. 發生了什麼：只講已確定的。
  3. 哪裡不合理、外界懷疑什麼。
  4. 逐一查證：官方文件怎麼寫、媒體怎麼報、兩者差在哪。
  5. 目前最合理的解釋，以及還不知道的事。
  6. 具體提問＋下一集鉤子。
- 口吻：冷靜、有把握，「我幫你把沒人講清楚的地方查出來」。帶一點揭露與解惑的感覺，不聳動、不喊口號。

## 三、事實紀律（硬規則）

- 可以問「這合理嗎？」「有人懷疑是…」，**不可以把沒有證據的陰謀寫成結論**。範本片的寫法：「但樂見，不等於設局。」
- 每個說法在畫面上標一種狀態：已確定／媒體報導（寫明誰報的）／分析推測／查不到證據（寫截至日期）。
- 時事一律上網查證，不靠記憶；上片當天要重查一次。畫面常駐「查證截至 YYYY/M/D」。
- 真實人物：只寫本人承認或官方文件有的部分，不提第三人姓名，不用定罪式用語。
- 不給投資建議，不寫哪檔會漲跌。
- 不出現真人肖像（包含剪影、替代物）與公司商標；文件畫面要標「示意，非文件原件」，照片標「示意照片」。

- **相關公司（使用者 2026/11/16**：「後續這些題材，有跟股票公司有關的 麻煩補充上去，觀眾會想知道是哪些公司」；從下一支起，現有片不改）：題材只要跟上市公司有關，就寫出是哪些公司＝公司名＋股票代號（例：輝達 NVDA、台積電 2330），最多 3 家，放畫面「相關公司」卡或旁白帶一句。只列查證過、確實跟這件事有關的公司，每家附出處與狀態標籤（公司公告／媒體報導（誰報的））。只寫「跟這件事有關」，不寫買賣、目標價、漲跌預測，不用「受惠股」「概念股」；畫面角落固定放「非投資建議」。文章 JSON 加一段「相關公司」：名稱、代號、跟這件事的關係、出處。公司卡算寫稿八條裡的 1 個事實（30 秒事實 ≤4 不變），不能因此塞爆。

## 四、畫面（檔案室＋國際新聞）

- `styleVersion: 3`、`stage: "dossier"`，加頂層 `news`（**一定要寫 `"layout": "fill"`**：上下留白各 ≤60px，使用者 2026/11/15 要求；渲染後跑 `python3 scripts/dossier/edge-check.py <slug>`）（新聞語彙：欄目「國際 INTERNATIONAL」、每鏡的電頭「地點・日期」、鏡號 01/07、下方地圖與地點連線、底部跑馬出處）。
- 頻道字樣：哩股哩股／查到底／數字，查過再信。
- 深色底、襯線大標、一個紅色強調；文件用米色紙卡；照片一律黑白低對比。
- 每鏡下方有一條字幕卡，左上小標寫這一鏡的性質（事件／四天前／兩種說法／外界懷疑／查證／還不知道／提問）。
- 節奏：每鏡事件間隔 0.5–1.0 秒（最長 ≤1.2 秒），前 3 秒至少 5 個事件；蓋章、狀態標籤落定後至少停 0.8 秒才換鏡。
- 事件時間只寫念到的字（cue），不手填秒數。

## 五、指令順序

    python3 scripts/dossier/make-photos.py <slug>        # 黑白照片
    node scripts/dossier/fetch-fonts.mjs <slug>          # 襯線字型子集；改了畫面上的字要重跑
    node scripts/ui/silent-timeline.mjs <slug>           # 無聲時間軸，先看畫面
    npm run validate <slug>
    node scripts/dossier/events.mjs <slug>               # 每鏡事件間隔
    # —— 等使用者上傳旁白 ——
    # 錄音複製到 public/audio/<slug>/ 後：
    node scripts/dossier/recording-timeline.mjs <slug> audio/<slug>/<檔名>.wav <句數>
    npm run validate <slug>
    npm run still <slug>
    npm run render <slug>                                # 產生的是無聲畫面
    # 用 ffmpeg 把錄音合進去（音量調到約 −16 LUFS、真峰值 ≤ −1.5 dBTP；指令在範本片的 voice.md）

- 成片只放旁白，不加背景音樂與音效。
- 錄音照原樣用，不加速；先確認每一句都有、只念一遍、和稿子一致。
- 某一鏡太短看不清時，可在該鏡加 `cutDelayF` 讓畫面晚幾幀換，聲音不動。

## 六、交片前檢查

- 數字、日期、引述和 `research.md` 一致；每個說法都有狀態標籤。
- 前 3 秒每 2 幀、全片每 0.25 秒抽格看過；沒有黑幀；每鏡的蓋章停得夠久。
- 回報要寫：片長、語速、捲舌指標（偏高要照實說）、已知問題、哪些沒檢查。
- 影片、音檔、照片不進 git。

## 七、範本片留下的已知問題（新片要避開）

- 最短的一鏡只有 1.6 秒，畫面比旁白晚約 0.3 秒才換：腳本每鏡至少留 12 個字。
- 有一鏡大標出來後約 1.2 秒只有大標和照片，沒有新事件。
- 開頭「三十三年」念得很快，自動對齊抓不準：開頭的數字不要連著念太快，或在念稿裡斷開。
- 短片沒有片尾卡，自動檢查會報 1 個錯，屬於已知狀況。
- 事實只對過搜尋摘要，照片授權未逐張確認：上片前要補。
