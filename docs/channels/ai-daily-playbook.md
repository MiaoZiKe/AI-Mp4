# AI 教學頻道：每支影片的製作手冊

範本片：`videos/short-ai/`（「問 AI 明年基本工資」，第 4 版，12.2 秒，使用者 2026/11/15 確認通過）。
規則全文另見 `docs/channels/ai-tutorial.md`（題目、實測、等距 2.5D 畫面、旁白、範本卡）；範本片的鏡頭寫法見 `videos/short-ai/README.md`，旁白做法見同資料夾的 `voice.md`。

## 一、分工

| 步驟 | 誰做 | 產出 |
|---|---|---|
| 1 選題（一則新聞配一招）、查證 | 自動 | `research.md` |
| 2 對 AI 真的實測（隨便問、這樣問各一次，原文存檔） | 自動 | `tests/*.json`、`tests.md` |
| 3 寫腳本、無聲預覽、念稿 | 自動 | `script.json`、九格圖、念稿 |
| 4 生成旁白（呼叫 Gemini TTS API，`tts-take.mjs`，音色 Sulafat、`voice.profile: "ai-report-v5"`） | 自動（使用者 2026/11/15：「以後都用呼叫 API 方式生成旁白」） | 一個 wav 檔 |
| 5 接旁白、對時間、渲染、片尾 LOGO 動畫＋音效 | 自動 | `out/<slug>.mp4`、字幕檔、九格圖 |
| 6 檢查、交片 | 自動，使用者看過才發布 | 成片＋已知問題清單 |

旁白（第 4 步，**2026/11/15 起改為 API 自動生成**，使用者原話：「以後都用呼叫 API 方式生成旁白」）：`voice.profile: "ai-report-v5"`、音色 Sulafat、模型 Gemini 2.5 Flash Preview TTS，`NODE_USE_ENV_PROXY=1 node scripts/tts-take.mjs <slug>` 整篇送 1 次（沒音訊最多再送 1 次，不准無限重試）。說明只有一句（`REPORT_AI_V5_LINE`，不改、不加長，長篇導演筆記會變慢變演）：

    用台灣人平常講話的口音，不特別捲舌、不兒化，像在跟朋友分享一個實用的小知識，語速比平常快、輕快有精神，語氣跟著內容起伏，講到重點加重一點、問句上揚，不拖尾音、不演，直接說：

**語速與起伏（2026/11/15 使用者聽完 caffaine-agent-loop 第一版配音：「以後語速要調快點 Follow 之前的影片速度，並且旁白需要再有點起伏，有點太平淡，不像是在介紹小知識的感覺」）**：目標＝short-ai 第 4 版速度，成片扣停頓 ≥5.4（理想 5.4–5.8）、含停頓 ≥4.9 音節/秒；模型自己念不到就用 `TAKE_ATEMPO`（上限 1.15）先加速整篇再對齊（`TAKE_ATEMPO=1.15 node scripts/tts-take.mjs <slug> --resplit`），幕間停頓用 `ALIGN_GAP_MAX=0.35 node scripts/align.mjs <slug> --force` 壓到 ≤0.35 秒（script.json 不寫 `pauseAfter`）；兩邊都做了還不到就照實回報數字。配音後各幕變短，字幕每段仍要 ≥1.2 秒（字幕少分行、少用標點斷句）、動畫太擠時刪次要動作。量測與送出提示全文寫進 `videos/<slug>/voice.md`。

## 二、內容規格

- 短片 12–20 秒；完整片 45–75 秒（骨架見 `ai-tutorial.md` 第 3 節）。
- ~~每支從一則台灣觀眾這幾天有感的新聞開始~~（使用者 2026/11/15：「題材太爛了…是跟人們使用 AI 上面功能上有關的」）→ **每支從一個熱門的 AI 使用題材開始**：Claude Code 入門、Vibe Coding 做自己的工具、AI 代理團隊／Skill／MCP 為主；找網路上已經很紅的教學，查證後用白話重講、補我們自己的實測。一支只教一招。題目表在 `docs/channels/caffaine-topics.md`。
- 不照抄別人的影片腳本與畫面：只拿事實與題目，出處寫進 `research.md` 與網站文章。
- 每支都有留言關鍵字：留言的人（IG 查得到有追蹤才傳）收到私訊，內容是詳細步驟＋官方文件連結＋網站 CaffAIne 隱藏分頁那篇圖文文章的直接連結，不只是文案。
- 片中的 AI 回答一定是真的實測，只能刪節、不能改字，畫面標「○○ 實測・日期（節錄）」。
- 第 0 幀就是實心大字（後果或數字），結尾是具體提問或下一集預告。
- 不碰真實商標與介面，不出現真人，不給投資建議，政治題材中立。

## 三、畫面

- 固定風格：等距 2.5D 粉彩小桌面（`stage: "iso"`；短片 `isoVersion: 3`＝`IsoShort.tsx`，完整片 `isoVersion: 2`＝`IsoFilm.tsx`）。
- 每鏡構圖不同，事件跟著念到的字（cue）出現，不手填秒數。
- 要讀的字放在轉正的白卡上，至少 28px；字幕每段至少停約 1.2 秒，畫面的打字要在旁白進下一句前打完。

## 四、所有頻道共用的版面規則（使用者 2026/11/15，每支都要照做）

1. **頻道 LOGO 固定在左上角**，全片不動，片尾卡也在。
2. **版面不要留大片空白**：主視覺、字幕、出處填滿 1080×1920；上方與下方不能看起來是空的（平台介面區不放重要文字，但要有淡色帶或背景元素）。
   - **數字（使用者 2026/11/15，經主控轉達：「紅框處還有空間，所以需要再調整，並每個頻道都要注意」）**：上方（進度條到 LOGO 之間）留白 ≤ 60px、底部留白 ≤ 60px；字幕卡下緣不超過 y1700，1700 以下只放出處與一條細頁尾帶。版面檢查：頂端或底端連續 60px 以上沒內容＝error（共用規則見 ai-mp4 CLAUDE.md）。
3. **片尾卡的 LOGO 要有動畫**（使用者 2026/11/15：「後面 LOGO 音效也要寫進去，他是需要的」）：
   - 每支片最後加約 3 秒的片尾卡（無旁白），頻道 LOGO 用動畫進場，之後出現頻道名、一句標語、下一集預告。
   - 風格要有 AI 感、配合等距 2.5D 的粉彩畫面，例如：LOGO 由小方塊從四面八方飛進來組成、游標打出頻道名、對話泡泡彈出變成 LOGO。進場約 1–1.5 秒，鎖定那一刻要有力道（放大回彈、波紋、粒子迸開），之後輕微呼吸。
   - 參考做法：科技頻道的 `src/components/three/LogoAnims.tsx`（飛入、掃描、合體、鎖定、文字逐字彈出、定格後反光）。AI 頻道要做自己的版本，不直接用科技頻道的圓環標誌。
4. **片尾 LOGO 要配音效**：
   - 用程式合成（ffmpeg），沒有版權問題；聲音對準畫面動作：飛入「咻」、組合「啵」、鎖定一下有分量的聲音、頻道名逐字彈出時一字一個音、下一集預告跳出「叮叮」。
   - 頻道名逐字彈出的那幾個音是固定旋律＝**頻道招牌音**，每支片尾都用同一段，讓觀眾記得。
   - 感覺：科技感加一點可愛（像小機器人、電子遊戲的音色），不要太吵。
   - 參考做法：科技頻道的 `out/tech-2nm/sfx/cute/`（合成指令）與 `out/tech-2nm.light-v9.mp4`（混音方式：音軌先補到和畫面一樣長，音效延遲到片尾卡開始的時間點，疊在背景音樂上，片尾那段沒有旁白）。
   - 交片時另附一個只有片尾音效的 MP3，方便在手機上確認有沒有聲音。
   - 音量（使用者 2026/11/15 聽完科技頻道片尾：「很棒，但可以再大聲點」）：片尾音效要比科技頻道 tech-2nm 那版更大聲，交片時寫片尾段的響度（LUFS）與峰值，峰值不超過 −1 dBTP。
5. **動作效果要清楚**：打字、飛卡、蓋章、放大鏡掃過都要有方向感，並跟旁白同步。

## 五、交片前檢查

- 實測原文與畫面一致（validate 會逐行比對 `verbatim`）；新聞數字和 `research.md` 一致。
- 前 3 秒每 2 幀、全片每 0.25 秒抽格看過；沒有黑幀；字幕來得及讀。
- 聲音和畫面一樣長（尾巴沒有被切掉），片尾音效聽得到。
- 回報要寫：片長、語速、捲舌指標（偏高要照實說）、已知問題、哪些沒檢查。
- 影片、音檔、圖片不進 git。

## 六、範本片留下的已知問題（新片要避開）

- 「先貼新聞」「只打這一句」兩段字幕各只停約 0.8、1.0 秒，來不及讀。
- 第 1–2 秒字幕已經在講「我們實測 Gemini」，輸入框還在打問題。
- 範本片是短片，還沒有片尾 LOGO 動畫與音效；新片要照第四節加上。
- 捲舌量測偏高（4.7 kHz），只是輔助數字，要人耳確認。

## 七、內容邏輯：三段結構（2026/11/15，四個頻道共用）

使用者 2026/11/15（經主控轉達）：「給我製作影片的內容邏輯，從開頭 3S 內抓住讀者目光到有邏輯的介紹文章，最後吊人胃口的結尾……輝達那篇影片就是這樣的邏輯我覺得很棒」。
全文在 tw-rotation `docs/marketing/channels/video_logic.md`；範本片 `videos/liguligu-jensen-pro/`。AI 教學（CaffAIne）照下面套：

| 段落 | 時間 | AI 教學怎麼做 |
|---|---|---|
| ① 鉤子 | 0–3 秒 | 一個反常、具體、已確定的 AI 事實：熱門工具的意外數字、官方說法和實測的差距。第 0 幀就是完整大字，1 秒內一個動作（框選、蓋章、劃線），前 3 秒 4–5 個畫面事件 |
| ② 有邏輯地講清楚 | 3–18 秒 | 一句一件事：發生了什麼（只講確定的）→ 哪裡對不上（官方 demo vs 實測、宣傳功能 vs 文件寫的限制）→ 我們實測（寫環境與日期，回答只刪節不改字）→ 每個說法標狀態 → 這一招怎麼用 |
| ③ 吊胃口的結尾 | 最後 3–5 秒 | 還不知道的事 → 具體二選一（「該不該用／值不值得等？」）→ 下集要測哪個（還沒實測就只能用問句） |

每句四個檢查：具體（數字、日期、名稱）／標狀態（已確定、媒體報導（誰報的）、分析推測、查不到（截至日期））／可以問、不下沒證據的結論／短（一句一件事，每鏡至少 12 字）。
不用：驚爆、內幕、你絕對想不到、細思極恐、連續反問。不誇大、不寫沒測過的效果。

交片時附「自查」結果（共用版四項＋AI 教學一項）：
1. 前 3 秒逐格：第 0 幀是完整主張？1 秒內有動作？
2. 拿掉所有問句後，剩下的句子沒有任何一句是沒證據的結論？
3. 結尾的「下一集」已經有報導或確定會做？
4. 每句都在 `research.md`／`tests.md` 找得到出處與狀態？
5. 片中 AI 回答和 `tests/*.json` 逐字一致（只刪節），工具名稱與測試日期在畫面上？

## 八、所有頻道共用的製作細則（使用者 2026/11/15，經主控轉達：「我上面有提到需要你影片版面要注意的，以及 LOGO 要有音效，和內容的動畫優化……叫他們也需要按照這注意製作」）

範本：分支 `claude/nifty-goodall-syke8a-1548` 的 `videos/tech-2nm`（v8，使用者：「非常好 太棒了」）；全文在該分支 CLAUDE.md「所有頻道的版面規則」與 `docs/channels/tech-daily-playbook.md` 第九節。CaffAIne 照下面做：

**版面**
- CaffAIne LOGO（八位元衝框）固定左上，每幕同位置、同大小，片尾卡也有。
- 頂、底留白各 ≤60px，多出來的空間先拿去放大主素材（等距桌面）。
- 字幕卡下緣 ≤y1700；1700 以下只放出處＋細頁尾帶。
- 主素材中央不被標籤遮住，但不要為了躲標籤去移動主素材。
- 換幕時兩張卡不半透明疊在一起；畫面上的小字 ≥30px。

**片尾 LOGO（約 3.6 秒；2026/11/16 Andy 定案，蓋掉 11/15 的桌面版）**
- 原話：看了 D 款後「為何背景一定是這樣，我需要結尾 LOGO 是獨立頁面特效動畫」；三款背景選了「3 純白景深」，並說「聲音有點太大聲，稍微柔和點」。
- **預設片尾＝獨立片尾頁「純白景深」**：沒有桌面、鍵盤、方塊、鋸齒桌緣，也沒有左上頻道牌，整頁就是 LOGO。程式 `CaffAnim.tsx` 的 `CaffEndcard`（variant S＋bg white），三個引擎（IsoShort／IsoAgent／IsoMeeting）的 `caffend` 片尾卡都用它。舊的桌面版（`CaffAnim` 預設 bg=desk）保留但不再預設；淺色、深色兩款背景（bg=light／dark）也留著備用。
- 動畫節奏：三張卡（紫、黃、白）從不同方向飛進來斜放成爆炸圖，電路連線亮起、掃描帶掃過 → 第 16 幀撞合輕震 → 第 30 幀鎖定：閃光、衝擊波、粒子迸開，像素方塊沿弧線飛進杯子 → 蒸氣資料點 → 「CaffAIne」逐字彈出、AI 藍色塊蓋上、白光掃過字標 → 標語、留言關鍵字 → 定格後卡片反光與粒子繞行。不做成轉圈載入圖示。
- 招牌音：程式合成，八位元／小機器人音色，**柔和版是預設**（`sfx-caffaine.py`；舊版加 `--classic`）：撞擊低頻起音放慢、音量收、鐘聲高頻收、掃頻起音放慢、整體兩段 4.6 kHz 低通；8 個字母配 8 個音的旋律與撞擊時間點（第 16、30、62 幀）不變。
- **響度：片尾段約 −14 LUFS（和正片 −16 差約 2 LU，不會突然變大聲），true peak ≤ −2 dBTP**，limiter latency=1；`mix-endsting.py` 預設值已改。實測柔和版：−13.9 LUFS、−2.8 dBTP。另附只有片尾音效的 MP3（`caffaine-endsting-soft.mp3`）。
- 片尾卡放「留言『關鍵字』拿完整資料」；念稿最後一句念出關鍵字。
- **★ 旁白標準音色定案（2026/11/16 Andy：「太棒了 動畫 文字 內容旁白都符合標準 特別是旁白以後的需要這音色」）**：以 caffaine-made-by-ai／two-answers／same-look／sketch-game 四支（11/16 第 3 版）為基準。設定：Sulafat、`voice.profile: "ai-report-v5"`、cmn-TW；**不後製加速**；段落停頓 0.6～0.8 秒、句間 ≥0.3 秒（`ALIGN_GAP_MIN`／`ALIGN_BEAT_GAP`，`scripts/caffaine/split-quad.py`）；同一批片的念稿放同一次 TTS 請求（音色一致）。量到的語速：扣停頓約 4.8～5.1、含停頓約 4.3～4.5 音節/秒，音高中位數約 210～222 Hz。以後 CaffAIne 新片一律照這組，不再用 `TAKE_ATEMPO` 加速。
- **素材依內容生成、要豐富、貼近文案（2026/11/16 Andy，全頻道）**：「素材需要依據內容生成，並需要豐富點，更貼近文案」。每一鏡的插圖從那句旁白的具體內容出發；一鏡至少一個主體＋一個對得上旁白關鍵詞的細節；不用與內容無關的通用圖（例如每鏡都放同一張桌面）；同一素材不跨篇重複使用。規劃方法見 `docs/channels/caffaine-visual-plan-1116.md`。
- **交件前獨立驗證＋打分（2026/11/16 Andy，全頻道）**：「生成後需要有人驗證」「每篇文章都需驗證後有人打分數 讓每次的文章能更好 以及需避免的問題」。
  1. 圖、影片、文案生成後，交件前一律由**非製作者**的審查角色（art-director、animation-director 或另派審查子 agent，sonnet 即可）驗證並留紀錄；沒有驗證紀錄不准排程。
  2. 審查者對每篇打分：內容邏輯、數據出處、素材貼近度、畫面品質、開頭吸引力五項各 1～10，取平均，寫進 `docs/channels/caffaine-scores.md`（日期、篇名、五項、總分、扣分原因、下次避免）。
  3. 製作下一篇前先讀最近 10 筆「下次避免」；每週檢討看分數趨勢。
- **片長與停頓（2026/11/16 Andy，全頻道，取代本頁先前的語速加快與幕間 ≤0.35 秒）**：「AI 有念清楚 ，但有點急促，盡量讓段落與段落之間有點停頓，並且內容控制45-60S」。
  1. 短影片一律 45～60 秒（不含片尾卡），旁白約 180～260 字；
  2. 語速不再後製加快（不用 `TAKE_ATEMPO` 加速）；
  3. 段落之間停頓 0.6～0.8 秒、句子之間至少 0.3 秒（剪輯插靜音，不靠模型自己停）；
  4. 60 秒的片數字最多 5 個、事實最多 6 個。
  全文在 tw-rotation `docs/marketing/channels/video_logic.md`「片長與停頓」。
- **送 TTS API 前必做念稿檢查**（2026/11/16 Andy：「開頭有點奇怪 不用"欸" AI的 "A" 也不見了 請確實在使用API前先確認內文有沒有錯誤再發送 告訴其他頻道也要」；科技透明圈句首「A I 晶片」被念成「欸」）：
  1. 跑 `python3 scripts/caffaine/tts-precheck.py <slug>`，逐句印出每幕 tts 全文，0 個 ⚠ 才准送：不准有「欸」等多餘語助詞或錯字，數字與單位念法要對；
  2. 句子（標點切開的每一段）不准用英文字母開頭：AI、ChatGPT、App 別放句首，改成「現在的 AI…」「這個 App…」；AI 一律寫「AI」，不拆成「A I」；

## 十三、退件教訓：會議紀錄那支「急促、不知道要幹嘛、聽不懂、沒邏輯」（使用者 2026/11/16）

使用者原話：「這影片給人的感覺很太急促，最大的問題是，他要表達什麼，前面開頭就不知道他要幹嘛，後面完全聽不懂，內容不具備邏輯，修正避免以後發生」。

CEO 自己對照念稿找到的原因：
1. **沒有一句話主旨**：寫稿前沒先定「看完的人會記得哪一句」。這支其實想說「叫 AI 整理會議紀錄，它會偷偷幫你補上沒寫的負責人；加一句規定就不會」，但片中從頭到尾沒講出這句。
2. **開頭沒給情境**：第一句「AI 整理六項待辦，一項負責人是它猜的」——觀眾不知道是誰、在做什麼、跟自己有什麼關係。要先一句情境（「開完會，把紀錄丟給 AI 整理待辦？」），再丟反常事實。
3. **塞了跟主旨無關的事實**：「第一次等了兩分五十秒」跟主旨無關，卻占了一整鏡。
4. **鏡與鏡之間沒有因果連接**：「同一句話再問一次，這次它寫了待指派」沒說為什麼要再問、代表什麼；觀眾跟不上。
5. **專有說法沒解釋**：「待指派」「未指定」對觀眾是兩個很像的詞，沒講差在哪。
6. **結尾跳題**：下集「期限怎麼查」跟這支的主旨無關。

防止再發生（寫稿前必做，交件附結果）：
- **先寫一句話主旨**（≤25 字，觀眾看完記得的那句），每一鏡都要能說出「這鏡怎麼幫主旨」；說不出就刪。
- **開頭兩句＝情境＋反常**：第 1 句讓觀眾知道在講哪件日常事、跟他有關；第 2 句才是反常事實。
- **一支最多 2 個數字／事實**，其餘放網站文章。
- **鏡與鏡之間要有連接詞**（所以、但是、結果、為什麼？因為…），念稿單獨念出來要像一段完整的話。
- **聽得懂測試**：只聽旁白、不看畫面，能不能講回主旨；做不到就重寫。
- 下集預告要跟這支主旨同一條線。

### 13.1 哩股哩股回覆的寫稿步驟（2026/11/16，照做）
1. 先寫一句話主旨（15 字內），寫不出來不開工。
2. 再寫結論句（觀眾要記住的那句）。
3. 只挑能撐主旨的 3～4 個事實，其他全砍（實測做到的也砍）；30 秒片數字最多 3 個、事實最多 4 個。
4. 排成「發生什麼 → 哪裡不對 → 證據 → 所以呢 → 還不知道」6～8 句，一句一件事。
5. 最後才寫鉤子：第一句同時有「觀眾熟悉的場景＋反常的確定事實＋懸念」。
6. 每句開頭回答上一句留下的問題（哪一項？為什麼？但是、所以、我們再試一次、結果）。
7. 旁白約 110～130 字／30 秒，每句之間約 0.3 秒氣口；寧可砍事實也不加快。
8. 結尾只留一個動作（留言關鍵字）；二選一或下集預告要嘛擇一，要嘛放貼文文案。
9. 自檢：不看畫面只念一遍能用一句話講回主旨；每句拿掉後下一句還接得上就代表多餘；沒介紹過的代名詞或專有名詞不准出現。
輝達範本逐句作用見主控轉來的回覆（鉤子→懸念→時間對照→矛盾→替觀眾問→外界說法→收斂→還不知道→二選一→下集）。
