# 「談晴說礙」頻道口吻規則（腳本檢查用）

每支片寫完腳本，逐條對這份文件。頻道介紹文在 `tanqing-shuoai-intro.md`；講話像不像真人的規則在 `../voice-natural.md`；這份只管「這個頻道說什麼、不說什麼」。
程式檢查：`stage: "notes"` 的片跑 `npm run validate <slug>` 會查第 3 節的禁用語（`scripts/notes/validate-notes.mjs` 的 `TANQING_BANNED`／`TANQING_SOFT`）；其他各條要人看。

## 1. 我們是誰

- 一句話：談晴，也說礙。說這一代的難，也說還在的光。
- 觀察者。看這一代年輕人怎麼生活：薪水、房價、租屋、催婚，和日子裡的一小段晴。
- **不是感情頻道**：不講男女交往技巧、不做兩性對話情境（sample-love-chat 的方向不對，不再沿用）。感情只在它是生活壓力的一部分時出現（例如催婚、不婚不生的統計）。

## 2. 口吻

| 要 | 不要 |
|---|---|
| 觀察者的主詞：「我們看見」「我們這一代」「這一代」「很多人」 | 對著觀眾下指示：「你應該」「你要」「你必須」 |
| 把事情說清楚：一個數字、它的意思、它的出處 | 評價與結論：「所以不要買房」「這個社會病了」 |
| 平靜。像一個人小聲對朋友講 | 抱怨、控訴、嘲諷；也不要播報、不要演講 |
| 晴是一件具體的小事（下班的夕陽、晚餐剛好很好吃、朋友一句「我懂」） | 雞湯：「加油就好」「一切都會好」「要相信自己」 |
| 結尾可以留一個問題：「你今天的一小段晴是什麼？」 | 結尾下指令或求互動：「記得按讚」「分享給」「傳給」「標記」 |

「你」只能出現在提問裡（你今天的一小段晴是什麼），不能出現在建議裡。

## 3. 禁用語

- **一律不用（validate 報 error）**：你應該、你必須、你一定要、加油就好、療癒、諮商、扎心、正能量、放過自己、擁抱自己、一切都會好、會好起來、別擔心、不要難過、相信自己。
- **看過再留（validate 警告）**：你要、加油、其實你、記得要、別忘了、一定會、值得、努力就、只要你、躺平、擺爛、小確幸。
- 另外照全專案的規則：不用中國用語、不兒化（`scripts/voice-profile.mjs` 的 `CN_TERMS`）。

## 4. 礙怎麼說

1. 一支片一個「礙」，用**一個有來源的數字**說。優先用官方統計（主計總處、內政部、勞動部、國發會、中央銀行），其次是學術調查；媒體民調要寫明是誰做的。
2. 一定上網查證，寫進該片的 `research.md`：來源、資料期間、查證日期、狀態（已確定／分析預期／尚未確定）。沒讀到原始統計表就照實寫，畫面上的精確值上片前要核對。
3. 數字出現時馬上用一句白話解釋（九倍多＝不吃不喝也要九年多）。
4. 不美化、不抱怨、不歸咎（不說是誰害的），不預測、不給投資或購屋建議。
5. 已發過的題目不重複：失業率、近七成員工領不到平均月薪、房價所得比（sample-talk-notes）、30–34 歲未婚比例（short-talk）、年總工時（talk-ep01，完整片）。新片先在這裡加一筆。

## 5. 晴怎麼說

1. 每支片結尾留一小段晴，佔全片大約五分之一，不超過三分之一。
2. 晴是看得到、摸得到的小事，寫成一個畫面，不寫成道理。
3. 用「不過」「還是」接，不用「所以」「因此」：晴不是礙的解答，只是同一天裡也有的東西。
4. 不把晴寫成安慰（「沒關係」「不是你的錯」）。介紹文那句「說清楚了，才知道不是自己不夠努力」是頻道的立場，單支片不必每次都講。

## 6. 骨架（短片 12–15 秒；長片照比例放大）

進場的字（欸、最近）→ 礙：一個數字 → 一句白話換算 → 觀察（我們、這一代）→ 晴 →（畫面上）一個提問。

短片（10–15 秒）從 2026/11/14 起照下一節「短片留存做法」：不用進場的字，第一句就是那個數字加處境；提問要念出來，而且問的是這支片的題目。

## 6-1. 短片留存做法（2026/11/14，使用者：「幫我調整成爆火影片，且符合這題材的語速音調」）

照做的樣片：`videos/short-talk/`（第 2 版，15.0 秒）。證據強弱照實標：**強**＝平台主管公開說法或上萬支影片的統計；**中**＝業者的基準報告或個別測試，數字彼此不一致；**弱**＝業界慣例或單一案例，沒有找到量化研究。查證日期 2026/11/14，只讀到搜尋結果摘要。

| 做法 | 這個頻道怎麼做 | 證據 |
|---|---|---|
| 前 2–3 秒決定去留 | 第 0 幀就有大標（那句話）和那個數字；第一句旁白就是「數字＋處境」（三十出頭，十個有六個還沒結婚），不用「欸」這類進場的字（上一版開頭「欸」之後停了 0.4 秒） | 中：多家業者報告都指向同一方向（例如「留住前 3 秒 70–85% 的影片總觀看多 2.2 倍」），但數字來源不明、彼此不一致。Instagram 負責人 Mosseri 2025/1 說排序最看「觀看時間、按讚、傳送」（Social Media Today 轉述）＝強，所以開頭不能掉人 |
| 開頭 2 秒內畫面要在動、有字 | 圖從第 1 幀開始一筆一筆描（十個人形 1.8 秒內畫完，念到「六個」六個轉橘）；第 0 幀先有淡線輪廓，截圖不是空的 | 中：NestScale 稱開頭有清楚的字加動作，3 秒留存最多高五成（業者數字） |
| 開頭有人聲 | 第 1 幀就開口，前面不留空拍 | 強：Emplifi 分析 10,110 支 Facebook Reels，開頭 3 秒有人聲的影片互動較好、10 秒留存高近 25%（是 Facebook 品牌頁資料，套到 IG／TikTok 要保留） |
| 代入感：講觀眾自己的處境 | 用「我們」和一個看得見的生活畫面（年夜飯又被問、笑笑低頭夾菜），不用「你應該」 | 中–弱：有業者稱「點出具體痛點的開頭」留存高約 23%（Opus Clip 的數字，沒有原始資料）。「數字加共鳴」這個組合沒有找到專門的研究 |
| 每幾秒一個事件 | 每 2–3 秒一件事（描線、出現一格、橘框、換頁）；動作維持安靜，不彈跳、不加音效 | 中：有業者稱約每 4 秒換一次畫面的影片平均留存 58%，對照靜態畫面 41%（單一來源） |
| 留白與停頓 | 停頓只放在兩個地方：轉到「晴」之前、提問之前（念稿在那裡分段）；其他句子連著講。不把停頓壓成等距 | 弱：沒有找到量化研究；這是配音與剪輯的慣例。上一版每句都停 0.9–1.3 秒，整支拖到 18.5 秒 |
| 結尾問一個答得出來的問題 | 最後一句念出提問，而且問的是這支片的題目（你最常被問哪一題？），畫面留一格空白給觀眾填；不寫「留言／分享給／傳給／標記」 | 弱：只有個案（書摘案例：片中放互動問題後留言與分享增加）。Mosseri 說「每觸及的傳送數」和觸及的相關性最高（2024 問答的說法，是相關不是公式）＝中，所以最後一格要讓人想傳給同樣被問的朋友 |
| 可以截圖的一句話 | 最後一格和第 0 幀都長得像頻道的一張貼文：字標、圖、襯線大標、出處、頁碼都在，沒有半句的字幕 | 弱：沒有找到研究；依據是上面「傳送」的說法與頻道貼文本來就是圖卡 |
| 短 | 10–15 秒、45–60 字 | 中：有網站稱 15 秒以下的影片平均完播 92%，沒有寫出處；方向和各家建議一致 |
| 大標和字幕不重複 | 大標就是正在念的那一句時，那一頁不放中文字幕（`props.caption: "en"`，只留英文）；其他頁的大標寫另一句（又是那一題） | 弱：自己的觀察（上一版同一句在畫面上出現兩次） |

不採用的做法：誇張的字卡、快切、音效、倒數、「看到最後」、聳動的問句（「你敢相信嗎」）。這些和頻道「安靜、不說教」衝突。

出處（搜尋結果）：Social Media Today〈Human speech and presence help drive Reels engagement〉（Emplifi 的統計）；SocialPilot、Dataslayer 等整理的 Mosseri 談排序訊號；NestScale〈Ways to increase hook rate〉；dev.to〈Hook Engineering〉、ttsvibes、joyspace 等業者文章（數字互相不一致，只當方向參考）；數位時代的書摘案例。

## 7. 影片風格（2026/11/14 起：照頻道貼文，`stage: "tanqing"`）

使用者的指示：「談晴說礙的風格需要改，你可以去看看該頻道，依據那頻道風格設計」。所以影片就是把頻道的輪播圖卡動起來，不另外發明一種風格。參考圖在 `tanqing-ref/`（11/12 發的三張），第一支是 `videos/short-talk/`，對照圖 `out/short-talk-vs-channel.png`。

- **紙與字**：暖米紙底 `#FBF4EA`（中間亮、四邊暗一點）；主字 `#3B2F2A`、次字 `#6E5A4E`；大標用襯線粗體（Noto Serif TC 900，88px，1–2 行、一行 ≤10 字），內文、字幕、出處用 Noto Sans TC。大標和字標裡的「晴」「礙」兩個字用橘棕色。
- **一個橘色**：一個畫面只有一個橘色重點（圖上 `#DB8C3D`，橘色字 `#A34A30`）：被標出來的那幾個、一圈框、一條虛線，或大標下面的一句話。其他都是灰線稿加白／米兩種填色。
- **圖**：線稿圓角圖形，一筆一筆描出來，念到哪裡畫到哪裡。現有四種：`people`（人形膠囊，標出其中幾個）、`form`（圓角表單框，有字的格、虛線的空格、橘框）、`bowl`（一碗麵，熱氣、辣椒）、`mark`（太陽雲朵）。要新圖形就在 `src/components/tanqing/TanqingVideo.tsx` 加一種，照同樣的線寬與填色。
- **固定位置**：左上太陽雲朵＋「談晴說礙」字標；左下「資料：來源」（最多兩行，沒有數字的頁寫「觀察描寫，非統計」）；右下小太陽加圓點當頁碼，一幕一頁，最後一頁沒有箭頭。
- **版面**（1080×1920，安全區上下 220、左右 64，左右邊距照貼文留 96）：字標 236｜圖 360–980｜大標 1030 起｜字幕 1338 起（中文 48px、英文 28px）｜出處與頁碼 1604 起。最小字 28px。大量留白。
- **動作**：安靜。每頁極慢推近約 2%；換頁是舊頁先淡出、新頁從右邊平移淡入；線條用描的、字用淡入；不彈跳、不閃、不用音效。第 0 幀就要有大標和那一個數字。
- **內容規則不變**：全片只放一個有來源的數字（寫 `claim` 指到 research.md）；結尾留一頁「晴」（`kind: "qing"`），最後一頁可以是提問；不出現真人、商標，不用 AI 生圖。
- 程式與檢查：`src/components/tanqing/`、`src/theme.ts` 的 `THEME_TANQING`／`LAYOUT_TANQING`、`scripts/tanqing/validate-tanqing.mjs`、`scripts/tanqing/fetch-fonts.mjs`（襯線字型子集）。寫法看 `videos/short-talk/script.json` 與它的 README。
- 2026/11/14 第 2 版加的三個寫法（都可省略，舊稿不受影響）：`props.caption: "en"`（這一頁不放中文字幕，大標就是正在念的那句）；`figure.scale`（1–1.3，圖整個放大，9:16 比貼文高）；`people` 第 0 幀先有淡線輪廓（`ghost: false` 可關），標籤接在橘色虛線右端。大數字 220px。
- 完整片（45–75 秒；第一支 `videos/talk-ep01/`，使用者 2026/11/14：「給我完整影片吧，並且是要有題材的」）：script.json 頂層寫 `tanqing.film: true`。可以有多個數字，但每張資料圖都要寫 `claim`；要有「為什麼」、口徑提醒（數字不能怎麼讀）、下一集、片尾卡；15–24 鏡、旁白 230–290 字。**2026/11/15 起完整片不放「晴」收尾與反思提問**（使用者：「後面廢話有點多，介紹完就好，不用特別說什麼天亮著什麼的」）：結尾＝介紹完 → 下一集 → 片尾卡（validate 對 film 不再要求 qing／ask；短片規則不變）。旁白一律 API 自動配音，`voice.profile: "tanqing-report"`（見 CLAUDE.md 各頻道音色）。多出來的 12 種圖形在 `src/components/tanqing/Figures.tsx`，寫法看該片的 README 與 storyboard.md。
- 以前試過、使用者不要的：觀察者筆記（`stage: "notes"`，實景照片加手寫字）、夜窗（`stage: "talk"`，實拍照片加夜色）。程式留著，新片不用。

## 7-舊. 畫面（觀察者筆記風格；已不用，留作紀錄）

- 安靜：實景照片（沒有可辨識的人臉、商標、門牌、車牌）加手寫字；一鏡一張照片，不快切、不用對話泡泡、不用誇張音效。
- 全片只放一個數字，數字旁邊寫資料期間與出處。
- 沒有數字的鏡，出處列寫「觀察描寫，非統計」或「照片為情境示意」。
- 不出現真實人物；不用 AI 生圖。

## 8. 旁白設定

- 音色 Sulafat、`gemini-2.5-flash-preview-tts`、`mode: "take"`、`languageCode: "cmn-TW"`。
- **2026/11/14 起用 `delivery: "plain"`（正常說話）**。使用者聽完 short-talk 第 1 版（`love` 預設＋`delivery: "chat"`＋人設、場景、情緒弧線，語氣寫「小聲」）：「我覺得正常說話，不要太奇怪，那個氣音很奇怪」。所以說明只送一句（`scripts/voice-profile.mjs` 的 `PLAIN_LINE`）：「用台灣人平常講話的口音，不特別捲舌、不兒化，用平常說話的音量和聲音，正常語速、不拖尾音、不用氣音、不演，直接說：」。**不要寫「小聲、聲音放低、像講心事、深夜」這類字，會引出氣音或耳語**；也不寫人設、場景、弧線（會變慢、變演，見 `videos/short-ai/voice.md`）。`voice.profile` 只留 `gender`／`accent`／`pace`／`delivery`。
- 語速目標 4.3–4.7 音節/秒（扣掉幕間停頓）。short-talk 第 2 版模型自己念到 4.2，加速 1.08 後 4.5。各幕用 `para` 分段：要停的地方才換段。
- 舊寫法（`love` 預設檔＋`delivery: "chat"`）只留給已配好的 `videos/sample-talk-notes/`。

## 9. 一定要守的

- 簡介與任何談到情緒低落的貼文，附「1925 安心專線（24 小時、免付費）」。
- 題材碰到自傷、憂鬱時不描述方法、不做診斷，也不說「諮商」「療癒」；只說看得見的事實與求助管道。
- 政治、房市、薪資題材保持中立，不指名批評，不給投資建議。

## 送配音 API 前的檢查（使用者 2026/11/16，所有有配音的頻道）
使用者：「開頭有點奇怪，不用"欸"，AI 的 "A" 也不見了，請確實在使用 API 前先確認內文有沒有錯誤再發送」。起因：別頻道念稿「A I 晶片…」句首字母被念成「欸」。
1. 送出前把每幕 `tts` 全文逐句印出檢查：不准有「欸」等多餘語助詞、錯字；數字與單位念法正確。
2. 句子不要用英文字母開頭；AI 直接寫「AI」，不要拆成「A I」。
3. 每次重配都花額度：檢查完才送，最終送出的 tts 全文留在該片 README／voice.md。
4. 成片交件前，人耳聽前 5 秒（我無法聽，交件時明確請使用者聽）。

## 片長與停頓（使用者 2026/11/16，全頻道）
使用者：「AI 有念清楚，但有點急促，盡量讓段落與段落之間有點停頓，並且內容控制 45–60S，這也提醒其他頻道」。
- 短影片一律 45–60 秒；旁白約 180–260 字，語速不加快。
- 段落之間停頓 0.6–0.8 秒，句子之間至少 0.3 秒（不夠就在剪輯時插靜音）。
- 60 秒的片數字最多 5 個、事實最多 6 個。
