# 旁白要像真人聊天，不要像演講（voice-natural）

使用者聽完 sample-ai-ui（音色 Sulafat）說：「旁白音色很好，但感覺還是太演講感覺，所以感覺有點 AI，需要更像真人一樣。」這份文件記三件事：量到什麼、最可能的原因、之後怎麼寫稿和寫提示。

**先講限制：寫這份文件的人聽不到聲音。** 下面的原因都是從量測數字、送出去的提示文字、和網路上的做法推出來的，每一條都標了「量到的」或「推測」。像不像真人，最後只有人耳能判斷；2026/11/13 當天 TTS 額度用完，沒有做任何新的錄音來驗證。

## 一、量到什麼（2026/11/13）

量的是兩段 Sulafat 錄音：sample-ai-ui（`.take-cf61b1d813.orig.wav`，模型原始輸出 15.4 秒）與 sample-love-chat（`.take-357dec22b3.raw.wav`，13.3 秒）。逐字時間用各片 `timeline.json` 的強制對齊結果；音高用自相關法估算；音量範圍用 ffmpeg `ebur128` 的 LRA。對照組是 `videos/what-is-server/voice.md` 的數字（D2 是使用者當時選中的那一段）。量測腳本沒有放進 repo（暫存在 scratchpad 的 `voice-natural/m2.py`）。

## 二、為什麼聽起來像演講（判斷，依把握程度排）

1. **稿子是書面句，不是講話的句子。（把握最高；稿子是看得到的事實，影響是推測）**
   sample-ai-ui 的五句每一句都是完整、對稱、收得很乾淨的句子：「Google 的官方指南說，好的提示詞有四塊：角色、任務、背景、格式。」這是簡報投影片的句型（先宣告有幾點，再一點一點唸）。整篇沒有一個語助詞、沒有半句話、沒有回頭補一句。模型拿到這種字，最合理的念法就是「報告」。Google 自己的提示指南與多家 TTS 廠商的文件都說同一件事：稿子本身的寫法決定念法，風格說明只能微調。
2. **模型把每個標點當成一次停頓，每一小段當成一個獨立的「包裹」。（量到的）**
   去掉停頓後字念到每秒 5.6–6.1 個，停頓卻佔了四分之一到三分之一的時間，而且停頓幾乎只出現在標點上。真人聊天是反過來的：很多逗號根本不停、一口氣帶過，反而會在句子中間「想一下」。這種「快速念一段、停、再念一段」的節奏就是照稿念的節奏。
3. **每一小段都是高起、往下收，連逗號也收。（量到的傾向，love-chat 很明顯；影響是推測）**
   真人話還沒講完時，逗號前的音高通常會掛著或微微往上，表示「我還沒講完」。每一段都收下來，聽起來就像一條一條宣布。
4. **每一段都差不多大聲。（量到的；LRA 1.9–2.6，比 what-is-server 任何一段都小）**
   真人講話會有「順口帶過」的小聲段和「這裡是重點」的大聲段。每段一樣用力，就是對著一群人講話的投射方式。
5. **提示裡的字眼把模型推向「俐落的主持人」。（推測）**
   sample-ai-ui 送出去的提示有：「明快、有精神」「乾脆俐落，直接講重點」「四個重點一個接一個點出來」「句子和句子之間不拖」。每支片固定加的兩句也是：「每個字都講得出來」「中文和英文都要念得標準、清楚」「句子講完才換氣」。這些都在描述一個「把稿子念好」的人。另外 Avoid 裡寫了「平平的、像機器念稿的語調」：有第三方實測指出，提示裡出現「平」這類字眼反而可能把模型帶往那個方向（非官方、未在本專案驗證）。
6. **後製把句間停頓壓成等距。（量到的，只有 sample-ai-ui）**
   為了趕到 14 秒，sample-ai-ui 對齊時用 `ALIGN_GAP_MAX=0.3` 把四個句間停頓全部壓到 0.27–0.30 秒，結果句號停得比句子裡的頓號（0.46–0.48 秒）還短。what-is-server 上一支「旁白糟糕」的片也有一樣的問題（句號 0.23 秒 < 逗號 0.39 秒）。另外還加速了 1.06 倍。這一條和模型無關，是我們自己造成的。
7. **試片太短、太趕。（推測）**
   63 個字要在 14 秒內講完五件事，沒有任何可以放鬆的地方。

沒有證據支持的說法：不是「音調太平」（音高起伏 17 半音，和使用者選過的 D2 一樣大）。使用者也說了音色很好，所以不換音色。

## 三、寫稿規則（最有效的一層）

原則：**稿子寫成「一個人對一個朋友講話時真的會說出口的字」**，再去檢查事實有沒有跑掉。

1. **開口先有一個「進場的字」**：欸、啊、好、你知道嗎、我跟你說。不要第一個字就是主詞加動詞的完整句。
2. **語助詞放在句尾和換氣的地方**，全片不要每句都有，同一個不連用。台灣口語常用的：

   | 寫法 | 用在哪 | 例子 |
   |---|---|---|
   | 欸 | 開頭叫對方、或句尾表示「你看」 | 欸，你問 AI 都只打一句話，對不對？／一樣的 AI 欸 |
   | 啊 | 句尾放鬆、理所當然 | 難怪啊／就是這樣啊 |
   | 啦 | 句尾，把話講輕、帶一點「這還用說」 | 難怪啦／官方指南就有寫啦 |
   | 喔 | 提醒、強調一下 | 一樣的 AI 喔／這個很重要喔 |
   | 齁（也有人寫 吼） | 句尾找對方附和，像「對吧」 | 難怪齁／補上去齁 |
   | 耶 | 小小的驚訝 | 真的有差耶 |
   | 嘛 | 理所當然 | 你又沒講清楚嘛 |
   | 蛤 | 一個字的反問，表示「什麼？」 | 蛤？只打一句話？ |
   | 對啊、對不對、是不是 | 自己附和、或丟回去問對方 | 對啊，難怪回得很普通 |
   | 其實、其實齁、我跟你說、你知道嗎、就是、然後、所以啊 | 句子開頭的墊字 | 其實 Google 官方指南有寫 |
   | 那個、嗯 | 想一下的墊字，全片最多一次 | 那個……叫角色 |

3. **自問自答**：把「有四塊：甲、乙、丙、丁」拆成「有四塊。哪四塊？甲、乙、丙，還有丁。」問句會讓音高自己往上，接下來的回答就不會又是「宣布」。
4. **長短句交錯**：一句 3–6 個字的短句後面接一句 12–18 字的，不要連三句一樣長。半句話可以單獨成句（「難怪啦。」「對啊。」「就這樣。」）。
5. **不要對稱、不要排比**：條列的最後一項前面加「還有」「然後」（角色、任務、背景，還有格式）；不要「不是…而是…」「既…又…」「第一…第二…」。
6. **用講話的詞換掉書面詞**：非常→超、很；因此→所以啊；相同的→一樣的；並且→然後；是否→是不是、有沒有；較為→比較；如此→這樣。口語連音照台灣人常寫的字寫（這樣子→醬、就是→就醬）**只在很隨興的頻道用，而且要先確認模型念得對**，預設不用。
7. **標點是節奏記號，不是文法記號**：真人不會停的逗號就拿掉（「你問 AI 是不是都只打一句話」中間不加逗號）；想要「想一下」才用「……」，全片最多 1–2 處；不用分號和冒號（冒號會念成「宣布」）。念稿版仍要守「兩個標點之間 ≤26 字」。
8. **限度**：
   - 事實不變。數字、出處、「已確定／分析預期／尚未確定」的分寸不能因為口語化而改掉（「更貼近」不能變成「一定更好」）。
   - 語助詞全片大約每 15–25 個字一個；超過就變成另一種假（刻意裝可愛、裝隨興）。
   - 字幕可以比念稿乾淨：念稿（`tts`）帶語助詞，字幕要不要一起帶由該片決定，但 cue 對的字兩邊都要有。
   - 股票、時事頻道用「輕」到「中」；感情、AI 教學可以到「中」；「重」只有使用者聽過說好才用。
   - 中國用語和兒化仍然禁止（`voice-profile.mjs` 的 `CN_TERMS`）。
9. **會念錯的風險（要人耳確認）**：欸有好幾個讀音，模型可能念成別的聲調；齁、蛤是口語字，模型可能念得很重或念錯；「……」可能拖太長。試聽時先聽這幾個字。

## 四、提示規則

1. **寫情境，不寫形容詞。** 說明要回答三件事：誰、在哪裡、對哪一個人講。例如「咖啡店裡兩個人並肩坐著，筆電開著，她湊過去看朋友的螢幕，一邊指一邊講」。Google 的指南把說明分成 Audio Profile（誰）、Scene（場景）、Director's Notes（怎麼演）三塊；官方範例也建議用具體情境代替「有活力」這種形容詞。
2. **不寫會導向朗讀或簡報的詞**：清楚、專業、沉穩、克制、認真、明快、俐落、有精神、乾脆、標準、字正腔圓、咬字清楚、一個重點一個重點。改寫成情境：「像剛發現好用的東西急著跟朋友講」「想到哪講到哪」「不是在上課」。
3. **只有一個聽眾。** 寫「旁邊沒有別人在聽」「坐在朋友旁邊」。對一群人講話就是演講。
4. **Avoid 只寫「哪一種節目」**（播報、簡報、線上課程講師、朗讀課文、購物台），不要描述壞聲音本身（平平的、像機器、沒有感情），避免反而把模型帶過去（第三方觀察，未驗證）。
5. **仍然不放台詞、不引用稿子。** 說明裡像台詞的句子會被念出來，本專案踩過；每句 60 字以內。標題用 `# AUDIO PROFILE`／`# SCENE`／`# PERFORMANCE`／`# TRANSCRIPT`：第三方實測 `DIRECTOR'S NOTES` 這個標題本身曾被念出來，本專案原本就沒用。
6. **不要在提示裡要求「快」「不要停」。** 要快就把稿子寫短。sample-ai-ui 的「句子之間不拖」「乾脆俐落」可能是每一段都念成急促小包裹的原因之一（推測）。
7. **程式支援（選填，不寫就和以前完全一樣）**：`voice.profile` 多兩個欄位——
   - `scene`：一句話的場景，會多一段 `# SCENE`。
   - `delivery: "chat"`：把固定的 Pacing／Articulation 兩句換成聊天版（「想到哪講到哪…停頓有長有短，逗號不一定要停」「平常講話的咬字就好，虛字和語助詞輕輕帶過…句尾不用每一句都收得很乾淨」），不再出現「每個字都講得出來」「念得標準、清楚」「句子講完才換氣」。
   - 四個頻道建議的場景句在 `scripts/voice-profiles.json` 的 `_chat`。寫法：`"profile": { "preset": "ai", "delivery": "chat", "scene": "…" }`。
   - 這兩個欄位**還沒有用錄音驗證過**，第一次用就是明天的試聽。

## 五、模型層：行內標籤

- `gemini-3.1-flash-tts-preview`（2026/4 發布）官方說支援 200 個以上的行內音訊標籤，可以在句子中間改變表情；支援 70 多種語言。第三方資料列出台灣華語是其中一種語言，並說非英文稿子建議標籤仍用英文寫。
- **沒查到的**：官方完整的標籤清單、標籤到底用方括號還是角括號（搜尋摘要兩種說法都有）、中文稿子裡停頓／笑／嘆氣實際有沒有效。官方文件頁（ai.google.dev）在這個環境連不上，只看到搜尋摘要。
- 本專案的狀況：現在用的 `gemini-2.5-flash-preview-tts` 行內標記容易被念出來，**不用**；3.x 會把導演說明念出來，所以 3.x 只送念稿。3.x 的行內標籤**沒有在本專案驗證過**。
- 建議：先用稿子和提示這兩層解決（明天的三段試聽）。如果還是不夠像，再另外花 1 次請求試 3.1 加一個英文標籤（例如在一處放短停頓、一處放輕笑），並用聽寫確認標籤沒有被念出來。這是之後的選項，不在明天的三次請求裡。

## 六、後製層

1. **不要把停頓壓成等距。** 短片要趕時間，先刪字，不要調 `ALIGN_GAP_MAX`。句號後的停頓要比逗號長，而且每個不一樣長；量到幕間停頓的最大與最小差不到 0.1 秒，就是被壓平了。
2. **保留模型自己的呼吸和停頓**（`voice.mode: "take"` 本來就是整篇一次生成、不重排）。切檔只去頭尾靜音，不逐段做音量正規化。
3. **加速上限照舊 1.08**，而且加速會把停頓一起縮短；能不加就不加。
4. **不要用壓縮器把音量壓平**；整條只做一次響度正規化（−16 LUFS）。
5. 量測當輔助：停頓落在非標點處的次數、逗號停頓的範圍、短語語速變異、LRA、每一小段的音高走向。**這些數字不能代替人耳。**

## 七、明天的試聽

稿子與指令在 `videos/sample-ai-ui/voice-natural-candidates.md`：輕／中／重三版，各 1 次請求，音色 Sulafat，輸出到 `out/voice-audition-v3/`。聽完請回答：哪一版最像真人、有沒有哪個語助詞很怪、會不會太刻意。
